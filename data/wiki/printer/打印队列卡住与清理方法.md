# 打印队列卡住与清理方法

> **适用对象**：公司IT支持人员、办公终端管理员  
> **适用场景**：Windows 系统（Windows 10/11）下本地或网络打印机出现“正在删除”、“错误 - 0x00000709”、“文档挂起”、“假脱机服务未响应”等现象  

---

## 一、常见症状识别

| 现象 | 可能原因 | 关联错误码/状态 |
|--------|-----------|----------------|
| 打印任务长期显示“正在删除”或“正在处理” | 打印假脱机器（Spooler）进程异常阻塞 | `0x00000005`（拒绝访问）、`0x00000709`（无法连接打印机） |
| 新任务无法进入队列，提示“打印机脱机” | Print Spooler 服务已停止或崩溃 | Windows 服务状态为「已停止」 |
| 队列中任务灰色不可取消，右键无响应 | 打印后台处理程序（spoolsv.exe）卡死或内存泄漏 | 任务管理器中 `spoolsv.exe` CPU 占用持续 >90% |
| 多台客户端共用同一共享打印机时部分卡住 | 共享主机端假脱机文件损坏或权限异常 | `ERROR_SPOOLER_NOT_ACTIVE`（0x0000070A） |

---

## 二、标准清理流程（Windows）

### ✅ 步骤 1：停止打印后台处理程序
1. 按 `Win + R`，输入 `services.msc`，回车  
2. 在服务列表中找到 **Print Spooler**  
3. 右键 → **停止**（若为灰色，先以管理员身份运行 `services.msc`）  

### ✅ 步骤 2：清空假脱机缓存目录  
> ⚠️ 注意：此操作将永久删除所有待打印文档（含未完成任务）  
- 打开资源管理器，定位至：  
  ```
  C:\Windows\System32\spool\PRINTERS\
  ```  
- **全选所有 `.shd` 和 `.spl` 文件** → 按 `Shift + Delete` 彻底删除（绕过回收站）  
- 若提示“文件正在使用中”，说明 Spooler 未完全停止，请返回步骤1确认服务状态  

### ✅ 步骤 3：重启打印服务  
1. 回到 `services.msc`  
2. 右键 **Print Spooler** → **启动**  
3. （可选）右键 → **属性** → 将「启动类型」设为 **自动（延迟启动）**，避免系统启动时冲突  

### ✅ 步骤 4：验证与恢复  
- 打开「设置 → 蓝牙和其他设备 → 打印机和扫描仪」  
- 选择对应打印机 → 点击 **管理 → 打印机属性 → 常规 → 打印测试页**  
- 若测试页正常输出，说明队列已恢复；否则检查驱动兼容性（见下文）

## 三、进阶排查与修复建议

### 🔧 驱动兼容性问题（高频诱因）
- **现象**：仅特定文档（如PDF/Excel）卡住，或升级 Windows 后首次出现  
- **解决**：  
  1. 卸载当前驱动（设备管理器 → 打印队列 → 右键打印机 → 卸载设备 → ✅「删除驱动程序软件」）  
  2. 从打印机厂商官网下载 **最新 WHQL 认证驱动**（非 Windows Update 自动推送版本）  
  3. 安装时勾选「使用推荐的端口」，禁用「启用双向通信」（部分型号存在协议冲突）  

### 🛑 权限异常（域环境常见）
- 若打印机为网络共享型，需确保：  
  - 共享主机上的 `C:\Windows\System32\spool\PRINTERS\` 目录对 `Everyone` 或 `CREATOR OWNER` 具有 **修改（Modify）权限**  
  - 组策略路径：`计算机配置 → Windows 设置 → 安全设置 → 文件系统`  

### 🧩 批量清理脚本（管理员权限运行）
```powershell
# 保存为 cleanup-printer.ps1，右键以「以管理员身份运行」
Stop-Service -Name Spooler -Force
Remove-Item -Path "$env:systemroot\System32\spool\PRINTERS\*" -Force -Recurse
Start-Service -Name Spooler
Write-Host "✅ 打印队列已清空，Spooler 服务已重启" -ForegroundColor Green
```

## 四、预防措施

| 措施 | 实施方式 | 频率 |
|------|----------|------|
| 定期重启 Print Spooler 服务 | 使用计划任务调用 `net stop spooler && net start spooler` | 每周日凌晨2点 |
| 禁用老旧 GDI 渲染模式 | 组策略：`计算机配置 → 管理模板 → 打印机 → 启用“启用高级打印功能”` | 部署新打印机时默认启用 |
| 监控假脱机目录大小 | 使用 PRTG/Zabbix 监控 `C:\Windows\System32\spool\PRINTERS\` 占用 >50MB 触发告警 | 实时监控 |

📌 **附：关键命令速查表**  
| 功能 | 命令（管理员 CMD） |
|------|---------------------|
| 停止服务 | `net stop spooler` |
| 启动服务 | `net start spooler` |
| 查看队列状态 | `printui.dll,PrintUIEntry /o /n "PrinterName"` |
| 重置所有打印机端口 | `rundll32 printui.dll,PrintUIEntry /ia /m "Generic / Text Only"` |

> ✅ 完成上述操作后，95% 的打印队列卡死问题可立即恢复。若仍异常，请结合事件查看器（`eventvwr.msc`）筛选「应用程序和服务日志 → Microsoft → Windows → PrintService」中的错误事件进一步分析。
