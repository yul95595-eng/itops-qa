# 新员工账号开通清单

> **适用对象**：IT 运维团队、HR 入职支持人员  
> **更新日期**：2024年10月15日  
> **版本号**：v2.3  

---

## 一、开通前提条件

新员工账号开通须在以下条件全部满足后方可启动：

- ✅ HR 系统中完成入职流程审批（状态为「已入职」）  
- ✅ 身份信息（姓名、工号、部门、岗位、直属上级）已同步至公司统一身份管理平台（IDM）  
- ✅ 邮箱域名策略已确认（默认使用 `@company.com`，特殊岗位如海外团队可选 `@company.global`）  
- ❌ 不得提前开通（如仅完成Offer签署但未报到）

## 二、标准开通项与交付 SLA

| 序号 | 系统/服务         | 开通内容说明                                                                 | SLA（工作日内） | 交付方式               | 关联系统       |
|------|-------------------|------------------------------------------------------------------------------|------------------|------------------------|----------------|
| 1    | 统一身份账号（AD/IDM） | 创建主账号（含sAMAccountName、UPN）、分配OU、启用LDAP同步                         | T+0（当日）       | 自动化脚本触发 + 人工复核 | Microsoft AD / JumpCloud |
| 2    | 企业邮箱（Exchange Online / 钉钉邮件） | 分配邮箱地址、配置邮箱别名（如 `zhang.san@company.com`）、启用防垃圾邮件策略           | T+0               | 自动化配额分配             | Microsoft 365 / 钉钉 Admin Console |
| 3    | 单点登录（SSO）     | 在 Okta / Azure AD 中添加应用访问权限（如 OA、CRM、ERP、GitLab、Jira 等预设应用组）     | T+1               | 权限组自动继承 + 手动补录   | Okta / Azure AD |
| 4    | 笔记本设备域账号    | 预置域加入凭证（含本地管理员密码、域账号初始密码），支持首次开机自动入域              | T+0（随设备发放）   | 加密U盘/扫码获取凭证        | SCCM / Intune   |
| 5    | VPN 账号            | 启用 SSL VPN 或 IPsec 访问权限，绑定所属部门安全策略（如禁止P2P、限制境外IP访问）      | T+0               | 自动同步至 FortiGate / Palo Alto | 网络安全网关     |
| 6    | 代码仓库（GitLab / GitHub Enterprise） | 创建账号、加入对应 Group（按部门+项目维度）、授予 `Developer` 默认角色                 | T+1               | GitLab API 自动注册         | GitLab CE/EE    |

> ⚠️ **SLA说明**：T = 新员工实际报到日（以HR系统“入职日期”为准）；遇节假日顺延，不跨周末。

## 三、开通操作步骤（运维执行）

### 3.1 账号初始化（AD/IDM）

1. 登录 IDM 管理后台 → 进入【入职账号批量创建】模块  
2. 输入工号列表（支持CSV上传），校验字段完整性（必填：姓名、工号、部门编码、邮箱前缀、直属上级工号）  
3. 点击「预检」：系统自动校验是否存在重名、工号冲突、OU路径无效等错误（常见错误码：`ERR_IDM_007` - OU不存在；`ERR_IDM_012` - 邮箱前缀含非法字符）  
4. 预检通过后点击「提交创建」，等待自动化任务完成（约90秒）  
5. 登录 AD 用户管理工具，验证账号状态为「已启用」且 `pwdLastSet = 0`（强制首次登录修改密码）

### 3.2 邮箱与协同服务配置

1. 在 Exchange Admin Center（EAC）中搜索新账号 → 点击「启用邮箱」→ 设置邮箱容量（默认 50GB）  
2. 添加邮箱别名（如需支持旧名/英文名）：`Set-Mailbox -Identity "张三" -EmailAddresses @{add="zhang.san@company.com","san.zhang@company.com"}`  
3. 同步至钉钉/飞书：调用 `POST /v1/users/import` 接口，传入 JSON 格式用户基础信息（含手机号、部门ID）  
4. 发送欢迎邮件模板（含初始密码、密码修改链接、IT支持联系方式）

### 3.3 SSO 权限分发

1. 在 Okta Admin → 【Directory】→ 【People】中搜索新员工姓名  
2. 点击用户 → 【Groups】→ 批量添加预设组（示例）：
   - `GRP-DEPT-0210`（研发一部）
   - `GRP-ROLE-DEV`（开发者通用权限）
   - `GRP-APP-CRM-READ`（CRM只读访问）
3. 检查【Applications】页签下各应用的分配状态是否为「Assigned」

## 四、验证与闭环

- ✅ **自助验证项（要求新员工完成）**：
  1. 使用账号登录 [https://my.company.com](https://my.company.com)（内网门户）
  2. 成功收发测试邮件（发送至 `it-support@company.com` 并抄送直属上级）
  3. 登录 Jira / GitLab / 钉钉，确认组织架构与权限可见

- ✅ **运维侧闭环动作**：
  - 在 ITSM 系统（如 ServiceNow）中关闭对应 Incident（编号格式：`INC-EMP-YYYYMMDD-XXXXX`）  
  - 更新《新员工开通台账》Excel 表（存放于 `\\fileserver\IT\Ops\Onboarding\`）  
  - 向HRBP发送确认邮件（主题：`【已开通】工号XXX 张三账号开通完成`）

## 五、附录：常见问题速查

| 现象 | 可能原因 | 解决方案 |
|------|----------|-----------|
| 邮箱无法登录，提示“账户被禁用” | AD账号未启用或邮箱未启用 | 运行 `Get-User "张三" \| fl Enabled, EmailAddresses`；若为False，执行 `Enable-Mailbox` |
| SSO登录后看不到Jira入口 | 未加入 `GRP-APP-JIRA-USER` 组 | Okta中手动添加该组，或检查组同步延迟（最长5分钟） |
| 首次VPN连接失败（错误691） | 密码未同步至RADIUS服务器 | 重置AD密码并勾选「用户必须在下次登录时更改密码」→ 再次重置并取消勾选 |
