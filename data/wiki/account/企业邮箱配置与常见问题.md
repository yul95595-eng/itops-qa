# 企业邮箱配置与常见问题

> 本文档适用于公司统一部署的 Microsoft Outlook/Exchange 邮箱服务（基于 Microsoft 365 E3 订阅），涵盖标准配置流程、客户端适配要点及高频故障排查指南。

---

## 一、标准邮箱配置流程（以 Outlook 桌面端为例）

### 1. 前置条件
- 已完成公司 AD 域账号激活，且邮箱已由 IT 管理员在 Microsoft 365 后台分配；
- 设备已加入公司域或已配置 Intune MDM 策略（Windows）；
- 网络环境允许访问 `outlook.office365.com`（端口 443）及 `autodiscover.outlook.com`。

### 2. 自动配置（推荐）
1. 打开 Outlook → 「文件」→ 「添加账户」；
2. 输入完整邮箱地址（如 `name@company.com`）→ 点击「连接」；
3. 系统自动调用 Autodiscover 协议获取 Exchange 服务器配置；
4. 输入域账号凭据（格式：`COMPANY\username` 或 `username@company.com`），勾选「保存密码」；
5. 完成验证后，收件箱、日历、联系人同步启动。

> ✅ **提示**：若自动配置失败，请检查 DNS 中是否正确解析 `autodiscover.company.com` CNAME 记录指向 `autodiscover.outlook.com`。

### 3. 手动配置（仅限特殊网络环境）
| 配置项 | 值 |
|--------|----|
| 服务器类型 | Microsoft Exchange |
| 服务器地址 | `outlook.office365.com` |
| 用户名 | `name@company.com`（必须为 UPN 格式） |
| 使用加密连接（SSL/TLS） | ✔️ 启用 |
| 服务器端口 | 443（HTTPS） |
| 身份验证方式 | Modern Authentication（OAuth 2.0） |

> ⚠️ 注意：手动配置需在 Outlook 设置中关闭「使用自动发现」选项（文件 → 账户设置 → 账户设置 → 双击账户 → 更改 → 取消勾选“使用自动配置”）。

## 二、移动端配置（iOS / Android）

| 平台 | 操作路径 | 关键参数 |
|------|-----------|----------|
| **iOS（iOS 15+）** | 设置 → 邮件 → 账户 → 添加账户 → Microsoft Exchange → 输入邮箱/密码 | 域字段留空；用户名填 `name@company.com`；服务器填 `outlook.office365.com` |
| **Android（Gmail App）** | Gmail → 左上菜单 → 设置 → 添加另一个账户 → Exchange → 输入邮箱 | 同上；启用「安全连接（SSL）」和「客户端证书（如已部署）」 |

> 💡 补充：Android 建议使用 Microsoft Outlook App（应用商店官方版本），兼容 MFA 和 Conditional Access 策略。

## 三、高频问题与解决方案

### ❌ 问题 1：Autodiscover 失败，提示 “无法连接到 Microsoft Exchange”
- **可能原因**：
  - 公司防火墙拦截 `autodiscover.*` 域名请求；
  - 本地 hosts 文件误写入 `autodiscover.company.com` 指向错误 IP；
  - 设备时间偏差 > 5 分钟（影响 OAuth Token 签名验证）。
- **排查步骤**：
  1. 运行命令 `nslookup autodiscover.company.com`，确认返回 `autodiscover.outlook.com`；
  2. 执行 `ping autodiscover.outlook.com`，确保可达性；
  3. 在浏览器访问 `https://autodiscover.company.com/autodiscover/autodiscover.xml`（应返回 HTTP 401 或 403，非 DNS 错误）；
  4. 校准系统时间（Windows：设置 → 时间和语言 → 同步时间）。

### ❌ 问题 2：登录时反复跳转至 MFA 页面，无法完成验证
- **典型错误码**：`AADSTS50076`（需要多重身份验证）或 `AADSTS50079`（需要进行条件访问检查）
- **解决方法**：
  1. 确认已注册公司认可的 MFA 方式（Microsoft Authenticator App / SMS / 电话）；
  2. 检查设备是否满足 Conditional Access 策略要求（如：Intune 合规状态、设备已加密、已安装公司证书）；
  3. 如为新设备首次登录，需通过公司自助门户（`https://myaccess.company.com`）完成设备注册。

### ❌ 问题 3：邮件发送失败，报错 “550 5.7.1 Client does not have permissions to send as this sender”
- **根本原因**：当前登录账号无权代表该发件地址发送邮件（常见于共享邮箱或代理发送场景）。
- **修复方式**：
  - 管理员需在 Microsoft 365 后台为该用户授予 `Send As` 或 `Send on Behalf` 权限；
  - 路径：**Microsoft 365 后台 → Exchange 管理中心 → 收件人 → 邮箱 → 右键目标邮箱 → 权限 → 编辑 Send As**。

### ❌ 问题 4：Outlook 同步缓慢或部分文件夹不显示
- **建议操作**：
  1. 清除 Outlook 缓存：关闭 Outlook → 运行 `%localappdata%\Microsoft\Outlook` → 删除 `.ost` 文件 → 重启 Outlook 触发重建；
  2. 检查账户设置中是否启用了「缓存 Exchange 模式」（推荐开启）；
  3. 在账户属性中调整「同步最近邮件」范围（默认为 12 个月，可临时设为 1 个月测试）。

## 四、附录：关键服务端点与健康检查

| 服务 | URL | 用途 | 推荐检测方式 |
|------|-----|------|----------------|
| Autodiscover | `https://autodiscover.company.com/autodiscover/autodiscover.xml` | 自动发现配置 | 浏览器访问 + 查看 HTTP 状态码 |
| Outlook REST API | `https://outlook.office365.com/api/v2.0/me/messages` | 应用集成调用 | 使用 Postman + OAuth Bearer Token 测试 |
| Exchange Web Services (EWS) | `https://outlook.office365.com/EWS/Exchange.asmx` | 旧版客户端兼容 | `Test-OutlookWebServices -Identity "name@company.com"`（PowerShell with EXO V2 Module） |

> 🔒 安全说明：所有通信必须通过 TLS 1.2+ 加密；禁止明文传输凭证；禁用 Basic Auth（公司已于 2023 年 Q3 全面停用）。
