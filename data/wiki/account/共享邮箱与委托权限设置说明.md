# 共享邮箱与委托权限设置说明

## 一、概述  
共享邮箱（Shared Mailbox）是公司为团队协作场景提供的非个人化邮箱资源，不绑定具体用户账号，支持多人同时收发邮件、管理日历及联系人。委托权限（Delegation）则用于授予特定用户对他人邮箱（如主管邮箱）的读取、发送或管理权限。本文档适用于 Microsoft 365（Exchange Online）环境，涵盖创建、配置及常见问题处理。

---

## 二、共享邮箱配置流程

### 2.1 创建共享邮箱（管理员操作）

> ⚠️ 前置条件：需具备「全局管理员」或「Exchange 管理员」角色

1. 登录 [Microsoft 365 管理中心](https://admin.microsoft.com)  
2. 导航至 **「Teams 和 Skype」→「共享邮箱」**（或直接访问 Exchange 管理中心 → **收件人 → 共享邮箱 → + 添加**）  
3. 填写以下信息：
   - 邮箱地址（如 `support@company.com`，需符合公司域名规范）
   - 显示名称（如“技术支持共享邮箱”）
   - 可选：添加别名、设置邮件流规则（如自动转发、分类标签）  
4. 点击「保存」，系统自动生成邮箱（无密码，不可登录）

### 2.2 添加成员并分配权限

| 权限类型         | 说明                                                                 | 是否可发送邮件 | 是否可查看已发送邮件 |
|------------------|----------------------------------------------------------------------|----------------|------------------------|
| **完全访问权限** | 可读写邮箱所有文件夹（收件箱、发件箱、草稿、日历等），但默认**不可发信** | 否             | 是                     |
| **发送为权限**   | 可以该共享邮箱名义发送邮件（From: support@company.com）               | 是             | 是                     |
| **发送代理权限** | 可代发邮件（显示为 From: 张三 <support@company.com>）                | 是             | 否（仅出现在发件箱）   |

✅ **推荐组合**：为协作成员同时授予「完全访问权限」+「发送为权限」

#### 操作步骤（PowerShell 示例）：
```powershell
# 连接 Exchange Online PowerShell（需提前安装模块）
Connect-ExchangeOnline -Credential (Get-Credential)

# 授予完全访问权限
Add-RecipientPermission "support@company.com" -Trustee "zhangsan@company.com" -AccessRights FullAccess

# 授予发送为权限
Add-RecipientPermission "support@company.com" -Trustee "zhangsan@company.com" -AccessRights SendAs
```

> 💡 提示：图形界面中可在「共享邮箱属性 → 权限」页手动勾选添加；PowerShell 更适合批量操作。

## 三、委托邮箱（Delegate Access）配置

适用于将个人邮箱（如部门负责人邮箱）授权给助理或协作者管理。

### 3.1 Outlook 客户端配置（用户自助）

1. 打开 Outlook（已登录被委托人账户）  
2. 文件 → 账户设置 → 账户设置 → 选中邮箱 → 「更改」→ 「更多设置」→ 「高级」选项卡  
3. 点击「添加」→ 输入委托人邮箱地址 → 设置权限级别（建议选「代理人」或「自定义」）  
4. 在「委托人的邮箱」下勾选所需权限（如：可查看收件箱、可编辑日历、可代表我发送邮件等）  
5. 点击「确定」保存  

### 3.2 Web 端（Outlook on the web）配置路径  
设置 → 查看全部 Outlook 设置 → **邮件 → 权限 → 共享邮箱** → 添加委托人并设定权限范围（含日历/联系人/任务同步选项）

## 四、常见问题与排查

| 现象 | 可能原因 | 解决方案 |
|------|----------|----------|
| 成员无法在 Outlook 中看到共享邮箱 | 未分配「完全访问权限」，或客户端缓存未刷新 | 检查权限是否生效（`Get-RecipientPermission`）；重启 Outlook 或执行「发送/接收 → 更新文件夹」 |
| 使用共享邮箱发信失败，提示“无法发送：无权限” | 仅配置了「完全访问」但未配置「SendAs」或「SendOnBehalf」 | 补充执行 `Add-RecipientPermission … -AccessRights SendAs` |
| 委托人收不到被委托邮箱的会议邀请更新 | 日历未启用「自动接受/拒绝」或委托权限中未勾选「编辑日历项目」 | 在被委托人 Outlook 中：文件 → 选项 → 日历 → 日历选项 → 启用「自动接受/拒绝会议请求」；检查委托权限设置 |
| 共享邮箱登录后显示为空白（OWA） | 浏览器兼容性问题或邮箱未完成初始化 | 清除浏览器缓存；等待 15–30 分钟后重试；确认邮箱状态为「已启用」（`Get-Mailbox support@company.com \| fl RecipientTypeDetails,UserPrincipalName`） |

## 五、安全与合规提醒

- ✅ 共享邮箱**不得用于存储敏感个人信息（PII）或受监管数据**（如身份证号、银行卡号），应遵循《公司数据分类分级指南》  
- ✅ 所有权限变更须通过 ITSM 工单审批，并在「权限审计日志」中留痕（路径：M365 合规中心 → 审计日志搜索 `Set-RecipientPermission`, `Add-RecipientPermission`）  
- ❌ 禁止将共享邮箱密码化（因其无登录凭证），严禁通过第三方工具导出完整邮件历史
