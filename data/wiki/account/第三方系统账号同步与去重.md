# 第三方系统账号同步与去重

## 概述  
本指南适用于公司 IT 运维团队及身份管理（IAM）负责人，用于规范第三方系统（如 Jira、Confluence、GitLab、Zoom、Salesforce 等）与公司统一身份源（如 Azure AD / 钉钉组织架构 / 自建 LDAP）之间的账号同步策略、技术实现及重复账号识别与清理流程。目标是保障账号唯一性、权限一致性与审计合规性。

---

## 同步机制说明

### 1. 同步方式分类

| 同步类型 | 触发方式 | 频率 | 典型场景 | 支持系统示例 |
|----------|-----------|------|------------|----------------|
| **主动推送（SCIM / REST API）** | 身份源系统主动调用第三方 API | 实时或准实时（≤30s 延迟） | Azure AD ↔ GitLab、Okta ↔ Zoom | GitLab (v15.0+)、Zoom (SCIM v2.0)、Workday |
| **定时拉取（LDAP Sync / CSV Import）** | 第三方系统定期从身份源拉取数据 | 每日 1–4 次（可配置） | 自建 LDAP ↔ Confluence（Crowd）、旧版 Jira Server | Confluence (via Crowd), Jira Server (CSV sync) |
| **Webhook 回调（Event-driven）** | 身份源变更后触发 Webhook 通知 | 秒级 | 钉钉组织变更 → 同步至内部审批系统 | 钉钉开放平台、企业微信（需自建中台） |

> ⚠️ 注意：不支持 SCIM 的系统（如部分 SaaS 定制版）应通过中间同步服务（如 Identity Bridge）封装适配层，禁止人工导表/手动录入。

## 账号去重规则与判定逻辑

### 2. 去重核心字段（优先级由高到低）

1. **主标识符（Primary ID）**：`userPrincipalName`（Azure AD）或 `employeeId`（HR 系统唯一工号）——强制全局唯一，不可修改  
2. **邮箱地址（Primary Email）**：以 `@company.com` 结尾的主工作邮箱，作为登录名和通信基准  
3. **姓名+部门+入职日期组合**：仅用于辅助校验（当主标识缺失时启用），需满足三者完全一致才视为潜在重复  

### 3. 重复账号判定流程（有序步骤）

1. **采集阶段**：从所有接入的第三方系统中提取以下字段：  
   - `external_id`（系统内原始 ID）  
   - `email`（主邮箱 + 别名列表）  
   - `display_name`, `given_name`, `family_name`  
   - `department`, `job_title`, `hire_date`（若支持）  
   - `status`（active/inactive/suspended）  

2. **标准化清洗**：  
   - 统一小写处理邮箱（`user@COMPANY.COM` → `user@company.com`）  
   - 去除邮箱别名分隔符（如 `user+alias@company.com` → `user@company.com`）  
   - 姓名字段去除首尾空格、全角字符、特殊符号  

3. **匹配比对（双模匹配）**：  
   - **强匹配**：`primary_email` 或 `employeeId` 完全一致 → 直接标记为重复  
   - **弱匹配**：`email` 不一致但 `employeeId` 缺失，且 `name + department + hire_date` 三者 100% 匹配 → 标记为「待人工复核」  

4. **冲突解决策略**：  
   - 若同一 `employeeId` 在两个系统中对应不同 `email`：以 HR 系统为准，自动更新第三方系统邮箱字段（需开启写权限）  
   - 若无 `employeeId` 但存在邮箱冲突：保留 `status=active` 且最近一次登录时间更近的账号，另一账号标记为 `duplicate_pending_deletion`（7 天宽限期）  

5. **生成去重报告**：输出 CSV 报告，含列：  
   `conflict_id`, `system_a`, `user_a_id`, `email_a`, `system_b`, `user_b_id`, `email_b`, `match_type`, `resolution_status`, `resolved_by`, `resolve_time`

## 常见问题与错误码参考

| 错误码 | 含义 | 排查建议 |
|--------|------|-----------|
| `SYNC_ERR_409_CONFLICT` | 同步时检测到邮箱/工号已存在 | 检查目标系统是否残留离职人员账号；确认 HR 系统未重复推送 |
| `SYNC_ERR_401_UNAUTHORIZED` | API Token 过期或权限不足 | 更新 OAuth2 token / SCIM Bearer Token；检查角色是否含 `scim:write:users` |
| `DEDUP_WARN_003_AMBIGUOUS_NAME` | 姓名+部门+入职日匹配但邮箱不同（如实习生转正未更新邮箱） | 关联 HRIS 工单号，人工核实用工状态 |
| `SYNC_ERR_500_LDAP_TIMEOUT` | LDAP 查询超时（>30s） | 优化 LDAP filter（避免 `(objectClass=*)` 全量扫描）；增加分页参数 |

## 附录：自动化脚本调用示例（Python + requests）

```python
# 示例：调用 SCIM 接口查询重复邮箱（GitLab）
import requests
headers = {"Authorization": "Bearer <SCIM_TOKEN>", "Content-Type": "application/scim+json"}
resp = requests.get(
    "https://gitlab.example.com/scim/v2/Users",
    params={"filter": 'userName eq "zhangsan@company.com"'},
    headers=headers
)
# 返回 200 且 Resources 数组长度 > 1 → 触发去重流程
```

> ✅ 最佳实践：所有同步任务须接入公司统一可观测平台（Prometheus + Grafana），关键指标包括：同步成功率、平均延迟、重复账号发现数/日、自动修复率。
