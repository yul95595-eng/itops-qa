# 域账号与邮箱账号的对应关系说明

## 1. 基本概念

- **域账号（Domain Account）**：由公司 Active Directory（AD）统一管理的登录凭证，用于访问内网资源（如文件服务器、内部系统、Windows 登录等），格式通常为 `DOMAIN\username` 或 `username@company.local`。
- **邮箱账号（Email Account）**：由 Microsoft Exchange Online（或本地 Exchange Server）托管的电子邮件账户，用于收发邮件、日历协作等，格式为 `username@company.com`。

> ⚠️ 注意：域账号与邮箱账号**逻辑上强关联，但技术上属于不同系统**。二者通过 AD 中的 `mail` 和 `proxyAddresses` 属性进行映射，非自动一一对应。

---

## 2. 默认映射规则（公司标准）

公司采用以下标准化命名策略建立映射关系：

| 字段 | 域账号示例 | 邮箱账号示例 | 映射依据字段（AD 属性） |
|------|-------------|----------------|--------------------------|
| 员工编号入职账号 | `EMP00123` | `emp00123@company.com` | `sAMAccountName` → 小写 + `@company.com` |
| 姓名拼音账号 | `zhangsan` | `zhangsan@company.com` | `sAMAccountName` → 小写 + `@company.com` |
| 企业邮箱别名（主邮箱） | — | `zhang.san@company.com` | `proxyAddresses` 中含 `SMTP:zhang.san@company.com`（大写 SMTP 表示主地址） |

✅ **关键约束**：
- 每个域账号**最多绑定 1 个主邮箱（SMTP:xxx）**；
- 可配置多个辅助邮箱别名（`smtp:alias1@company.com`, `smtp:alias2@company.com`），不参与登录认证；
- `mail` 属性必须与主邮箱地址一致，否则 Outlook 自动发现（Autodiscover）可能失败。

## 3. 常见异常场景与处理步骤

### ❌ 场景1：域账号可登录，但无法收发邮件  
**可能原因**：  
- AD 中 `mail` 属性为空或格式错误（如缺少 `@company.com`）；  
- `proxyAddresses` 未设置主邮箱（无 `SMTP:` 大写条目）；  
- Exchange Online 中该用户未启用邮箱（`RecipientTypeDetails = UserMailbox` 缺失）。

**排查与修复步骤**：  
1. 使用 PowerShell（以域管理员身份）连接 AD：  
   ```powershell
   Get-ADUser -Identity "zhangsan" -Properties mail,proxyAddresses | Select-Object SamAccountName,mail,proxyAddresses
   ```
2. 检查输出中 `mail` 是否为有效邮箱（如 `zhangsan@company.com`）；  
3. 检查 `proxyAddresses` 是否包含且仅有一个 `SMTP:zhangsan@company.com`（注意大小写）；  
4. 若缺失，执行修复命令：  
   ```powershell
   Set-ADUser -Identity "zhangsan" -Email "zhangsan@company.com" 
   Set-ADUser -Identity "zhangsan" -Add @{'proxyAddresses'='SMTP:zhangsan@company.com'}
   ```
5. 等待 Azure AD Connect 同步（默认周期：30 分钟），或手动触发同步：  
   ```powershell
   Start-ADSyncSyncCycle -PolicyType Delta
   ```

### ❌ 场景2：邮箱能收发邮件，但无法用邮箱账号登录 OA/VPN 等系统  
**原因**：多数内部系统认证依赖 `sAMAccountName` 或 `userPrincipalName`（UPN），**不支持直接使用邮箱地址登录**。  
**解决方案**：  
- 登录时请使用域账号格式：`zhangsan` 或 `COMPANY\zhangsan`；  
- 如需支持邮箱格式登录，需在 AD 中将 `userPrincipalName` 设置为邮箱值（例如 `zhangsan@company.com`），并确保该 UPN 在域内唯一且已通过 DNS 验证（需提前配置 `company.com` 为可信 UPN 后缀）。

## 4. 管理规范与注意事项

- ✅ **新增员工**：HR 提交入职流程后，IT 自动创建 AD 账号，并按 `sAMAccountName@company.com` 规则初始化主邮箱；
- ✅ **离职/转岗**：禁用 AD 账号前，须先归档邮箱数据并解除 Exchange 邮箱绑定（避免误删邮件）；
- ⚠️ **禁止手动修改** `proxyAddresses` 或 `mail` 属性（除 IT 运维外），否则可能导致 Autodiscover 故障、Outlook 配置失败；
- 📌 所有邮箱别名变更须通过 [IT 服务门户 → 邮箱管理] 提交申请，由 AD/Exchange 管理员统一操作。
