# 域账号密码复杂度与过期策略

> **适用范围**：公司 Active Directory（AD）域环境下的所有员工域账号（含服务账号、管理员账号）  
> **生效时间**：策略配置后即时生效（新密码策略对下次修改密码时强制执行）  
> **责任部门**：IT 基础设施部（账号与身份管理组）

---

## 一、密码复杂度要求（Password Complexity）

AD 域默认启用「密码必须符合复杂性要求」策略（`Password must meet complexity requirements`），启用后密码需同时满足以下全部条件：

| 要求项 | 具体说明 | 示例（合规） | 示例（不合规） |
|--------|----------|--------------|----------------|
| **最小长度** | ≥ 8 个字符 | `Abc123!X` | `abc123!`（7位） |
| **字符类型覆盖** | 至少包含以下四类中的三类：<br>• 大写字母（A–Z）<br>• 小写字母（a–z）<br>• 数字（0–9）<br>• 特殊符号（如 `! @ # $ % ^ & * ( ) _ + - = [ ] { } \| ; : ' ", . < > ? /`） | `P@ssw0rd2024`（大+小+数+特殊）<br>`MySecur3!`（大+小+数+特殊） | `password123`（缺大写+特殊）<br>`PASSWORD!`（缺小写+数字） |
| **禁止常见弱口令** | 系统自动拒绝包含用户名、全名、"password"、"admin"、"123456" 等字串的密码（基于 AD 内置黑名单及公司自定义扩展词库） | — | `zhangsan123`（含用户名）、`Welcome2024!`（含常见前缀） |
| **历史密码限制** | 启用「强制密码历史」策略，最近 **24 次**已使用密码不可重复（防止循环复用） | — | 第25次设置与第1次相同密码 → **拒绝** |

> ⚠️ 注意：若通过 Azure AD Connect 同步至 Microsoft Entra ID（原 Azure AD），还需额外遵守 [Microsoft 密码策略](https://learn.microsoft.com/en-us/azure/active-directory/authentication/concept-sspr-policy) 的补充限制（如禁用某些特殊符号 `"`、`\`、`/` 在云侧）。

## 二、密码过期策略（Password Expiration）

公司统一实施**强制定期更换策略**，以降低长期口令泄露风险：

### ### 1. 核心参数配置（AD 组策略对象 GPO）

| 策略路径 | 设置值 | 说明 |
|----------|--------|------|
| `Computer Configuration → Policies → Windows Settings → Security Settings → Account Policies → Password Policy → Maximum password age` | **90 天** | 密码最长有效时间；到期前 14 天起，用户登录时将收到图形化提醒 |
| `Minimum password age` | **1 天** | 防止用户通过“改回旧密码”绕过历史限制（如当天改两次即复用） |
| `Enforce password history` | **24 个密码** | 见上文“历史密码限制” |
| `Password never expires` 属性 | **仅限服务账号/关键系统账号启用**，须经 IT 安全审批并登记备案 | 普通员工账号禁止勾选此选项 |

### ### 2. 用户端行为与提示机制

当密码即将过期或已过期时，系统按以下逻辑响应：

1. **到期前 14 天起**：Windows 登录界面右下角弹出通知：“您的密码将在 N 天后过期，请及时修改”；
2. **到期前 3 天起**：每次登录成功后，桌面右下角持续显示气泡提示（含“立即修改”快捷按钮）；
3. **密码过期当日**：
   - 用户仍可登录（利用缓存凭据），但**首次打开任意域资源（如文件共享、OA 系统、邮箱 Webmail）时强制跳转至密码修改页**；
   - 若未在 2 小时内完成修改，后续访问将返回 HTTP 401 或 Kerberos 错误 `KDC_ERR_KEY_EXPIRED (0x12)`；
4. **过期超 30 天未修改**：账号被 AD 自动禁用（`userAccountControl` 属性中 `ACCOUNTDISABLE` 标志置位），需联系 IT 服务台人工解锁。

## 三、例外处理与审批流程

| 场景 | 处理方式 | 审批要求 | 记录位置 |
|------|----------|-----------|------------|
| 因业务系统限制无法满足复杂度（如某老旧 ERP 只支持 6 位纯数字） | 提交《弱密码豁免申请》，附系统截图、安全评估说明及临时加固方案（如网络隔离、MFA 补偿） | 需信息安全管理岗 + 应用系统负责人双签 | ITSM 工单系统（分类：Identity/Password-Exception） |
| 管理员账号需长期固定密码（如自动化脚本依赖） | 必须启用「密码永不过期」+ 强制绑定 MFA（如 Windows Hello for Business 或 FIDO2 安全密钥） | 需 CISO 办公室书面批准 | AD 用户属性备注栏 + 《特权账号台账》Excel（加密存储于安全共享盘） |
| 员工离职/转岗触发账号冻结 | 系统自动执行：禁用账号 + 清除所有 Kerberos TGT/ST 缓存 + 撤销邮箱代理权限 + 同步禁用 Teams/SharePoint 权限 | 无需人工审批（HRIS 系统自动触发） | AD 日志（Event ID 4725）、Azure AD Sign-in Logs |

## 四、自查与排错指引

### 常见错误码与解决方法：

| 错误现象 | 错误代码 / 日志线索 | 排查步骤 |
|----------|---------------------|-----------|
| 修改密码时提示“密码不符合复杂性要求” | 事件查看器 → `Security` 日志，Event ID **4723**（失败尝试）或 **4724**（成功修改） | ① 检查是否输入了空格或全角字符<br>② 使用 [Microsoft 网络密码检查器](https://aka.ms/PasswordCheck) 验证强度<br>③ 确认当前策略是否由上级 GPO 覆盖（运行 `gpresult /h report.html`） |
| 密码已过期但仍能登录桌面 | `net user <username> /domain` 显示 `Password expires: Never` | 检查该账号是否被误设为 `Password never expires`（AD 用户属性 → Account 页签）→ 立即清除并重置密码 |
| 修改后 Outlook 无法收发邮件（提示“用户名或密码错误”） | Exchange Online 日志：`Error Code: 0x8004011D` | ① 确认 Outlook 是否使用现代身份验证（Modern Auth）<br>② 清除 Windows 凭据管理器中旧的 `MicrosoftOffice16` 条目<br>③ 重启 Outlook 并重新登录 |

> ✅ **最佳实践建议**：  
> - 推荐使用公司统一部署的 **Bitwarden 企业版** 管理个人密码，并启用「密码生成器」自动创建合规强密码；  
> - 所有远程办公设备须安装公司 MDM 客户端，确保密码策略同步生效（尤其 macOS/iOS 设备通过 DEP 配置）；  
> - 新员工入职培训中必须包含《域账号安全使用规范》实操演示（含密码修改全流程）。
