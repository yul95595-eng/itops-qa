# 邮箱客户端无法收发信排查指南

> **适用对象**：公司 IT 支持人员、终端用户自助排查参考  
> **更新日期**：2024年6月  
> **知识域**：账号与邮箱  

---

## 一、常见现象分类

| 现象类型         | 典型表现                                                                 |
|------------------|--------------------------------------------------------------------------|
| **完全无连接**   | 客户端提示“无法连接服务器”、“连接超时”、“SSL握手失败”等                   |
| **可收不可发**   | 能正常拉取新邮件，但发送时提示“SMTP 认证失败”、“535 5.7.8 Authentication failed”等 |
| **可发不可收**   | 邮件能成功发出，但收不到新邮件，IMAP/POP3 连接中断或同步为空                |
| **部分异常**     | 仅特定联系人收/发失败；大附件失败（报错 `552 5.3.4 Message size exceeds fixed limit`） |

---

## 二、基础检查项（用户自助）

请按顺序逐项确认：

1. **网络连通性验证**  
   - 打开命令行（Windows：`cmd`；macOS/Linux：`Terminal`），执行：  
     ```bash
     ping mail.company.com
     telnet mail.company.com 993  # IMAP over SSL
     telnet mail.company.com 465  # SMTP over SSL
     ```
     ✅ 预期结果：`ping` 可通；`telnet` 成功建立连接（黑屏/空白响应即为成功）  
     ❌ 若失败：检查本地防火墙、代理设置、DNS 解析（尝试 `nslookup mail.company.com`）

2. **账号凭证有效性**  
   - 登录 [Webmail 系统](https://webmail.company.com) 验证账号是否可正常登录及收发  
   - 检查是否启用「应用专用密码」（如启用 MFA，需在账号安全中心生成并用于客户端）

3. **客户端协议与端口配置核对**（以公司标准邮箱服务为准）

| 协议 | 加密方式 | 端口 | 推荐设置                     | 注意事项                         |
|------|----------|------|------------------------------|----------------------------------|
| IMAP | SSL/TLS  | 993  | 启用 SSL，验证服务器证书       | 不要勾选“忽略证书错误”              |
| SMTP | SSL/TLS  | 465  | 启用 SSL，SMTP 身份验证开启     | 用户名必须为完整邮箱地址（如 user@company.com） |
| POP3 | SSL/TLS  | 995  | 仅限历史兼容场景，不推荐新部署 | 同步后默认删除服务器副本（可调）        |

> ⚠️ 常见错误配置：  
> - 混淆 STARTTLS（端口 587）与 SSL（端口 465）；  
> - SMTP 未开启身份验证，或用户名填写为短用户名（如 `user` 而非 `user@company.com`）。

## 三、进阶排查（IT 支持人员）

### 3.1 查看客户端日志（关键线索来源）

- **Outlook**：文件 → 选项 → 高级 → Outlook 日志记录 → 启用 → 复现问题 → 查看 `%localappdata%\Microsoft\Outlook\Logging\`
- **Thunderbird**：菜单 → 帮助 → 故障排除信息 → “打开日志控制台” → 设置 `mail.log` 相关选项
- **移动端（iOS/Android）**：需开启调试日志（参考厂商文档），重点关注 `AUTH`, `LOGIN`, `NOOP`, `CAPABILITY` 等关键词

### 3.2 服务端侧关键检查点

| 检查项               | 操作命令 / 路径                              | 异常信号示例                          |
|----------------------|---------------------------------------------|---------------------------------------|
| 邮箱配额是否已满      | `Get-MailboxStatistics -Identity user@company.com \| fl TotalItemSize` （Exchange） | `TotalItemSize: 99.8 GB (107,174,182,400 bytes)` |
| SMTP 发送限制触发      | 查阅 Exchange Transport Logs 或邮件网关审计日志      | `550 5.2.2 Mailbox full` 或 `452 4.3.1 Insufficient system resources` |
| IP 黑名单/速率限制     | 检查邮件网关（如 Proofpoint/Symantec）策略日志         | `REJECT: Blocked by IP reputation policy` |
| TLS 版本兼容性问题     | 在服务器执行 `openssl s_client -connect mail.company.com:993 -tls1_2` | `SSL handshake failed` / `protocol error` |

### 3.3 常见错误码速查表

| 错误码         | 含义说明                            | 推荐操作                                  |
|----------------|-------------------------------------|-----------------------------------------|
| `535 5.7.8`    | SMTP 认证失败（用户名/密码/应用密码错误）     | 重置应用专用密码；确认客户端使用完整邮箱地址作为用户名       |
| `554 5.7.1`    | 发件人地址被策略拒绝（如未认证域、伪造发件人）    | 检查发件人策略（SenderID/SPF/DKIM）、确保使用公司授权 SMTP 中继 |
| `421 4.7.0`    | 连接被临时拒绝（服务器过载/连接数超限）        | 等待 5 分钟后重试；检查客户端是否多设备重复登录同一账号         |
| `550 5.1.1`    | 收件人地址不存在或邮箱已禁用              | 核对收件人邮箱拼写；通过 AD/Exchange 控制台确认账户启用状态     |

## 四、附录：快速复位建议流程

当用户无法定位具体原因时，推荐按以下顺序执行（平均修复率 >85%）：

1. ✅ 清除客户端缓存与配置（Outlook：`File → Account Settings → Remove Account`；Thunderbird：新建配置文件）
2. ✅ 使用 Webmail 确认账号功能正常（排除账号冻结、策略拦截）
3. ✅ 重装轻量客户端（如 Outlook for Mac / Windows Mail / Spark）测试
4. ✅ 提交工单至 IT 服务台，并附带：
   - 客户端类型与版本（如 Outlook 2021 MSO 2405.xxxx）
   - 完整错误截图（含时间戳）
   - `telnet` 和 `nslookup` 执行结果文本
