# 账号生命周期管理与自动化

## 概述  
账号生命周期管理（Account Lifecycle Management, ALM）是指对员工/用户在公司信息系统中数字身份的**创建、启用、权限分配、变更、停用、删除**等全过程进行标准化、可审计、自动化的管控。本规范适用于公司所有内部员工、外包人员、合作伙伴及系统服务账号，覆盖 Active Directory（AD）、企业邮箱（Exchange Online / 邮箱网关）、SaaS 应用（如钉钉、飞书、Jira、Confluence）、云平台（阿里云 RAM、AWS IAM）等核心身份源。

> ✅ **目标**：实现账号开通 ≤ 1 个工作小时、离职账号自动冻结 ≤ 15 分钟、权限回收率 100%、审计日志保留 ≥ 180 天。

---

## 生命周期阶段与关键动作

| 阶段 | 触发条件 | 主责系统 | 自动化动作 | 人工介入点 |
|------|-----------|------------|----------------|----------------|
| **创建** | HR 系统推送入职数据（含部门、职级、岗位、直属上级） | HRIS → IAM 中台 | 自动同步 AD 用户、生成邮箱（name@company.com）、分配默认 OU 和安全组；触发 SaaS 应用账号预配（SCIM） | 需人工确认特殊权限（如管理员、财务类） |
| **启用** | 入职日期当天 08:00 | IAM 中台 | 解锁 AD 账号、激活邮箱、发送欢迎邮件（含首次登录指引+密码策略链接） | 无（全自动） |
| **变更** | HRIS 同步调岗/转正/职级变动 | HRIS → IAM 中台 | 自动更新 AD 属性（department/title）、迁移 OU、增删对应业务组权限；同步更新邮箱别名与通讯组归属 | 需人工审批跨部门/跨BU 权限变更 |
| **停用** | HRIS 推送离职日期（或“已离职”状态） | IAM 中台 | 立即禁用 AD 账号、禁用邮箱收发、撤销所有 SaaS 应用会话、移出所有权限组；保留账号 30 天供审计 | 离职面谈后可申请延长停用期（≤7 天），需直属上级+IT 安全双审批 |
| **删除** | 停用满 30 天且无延期审批 | IAM 中台 + 定时任务 | 彻底删除 AD 对象、归档邮箱数据至合规存档库（保留 7 年）、清除所有 SaaS 应用账号及关联数据（依 GDPR/《个人信息保护法》执行） | 法务/合规团队可发起数据保留豁免申请 |

## 自动化架构与集成方式

### 核心组件
- **统一身份中台（IAM）**：基于 ForgeRock 或自研平台，作为身份数据中枢，对接各下游系统。
- **HRIS（如北森/薪人薪事/Meta HR）**：唯一可信身份源，通过 Webhook + OAuth2.0 实时推送事件。
- **目录服务**：Active Directory（混合云环境）+ Azure AD Connect 同步引擎。
- **邮箱系统**：Exchange Online（O365）或自建 Coremail，通过 Graph API / SMTP 网关集成。
- **SaaS 应用层**：支持 SCIM 2.0 协议的应用（如 Jira Cloud、Okta 应用目录）直连；不支持 SCIM 的通过 API + 定制 Connector 管理。

### 关键自动化流程（以离职处理为例）

1. HRIS 发送 `employeeStatusChanged` 事件（含 `status=terminated`, `terminationDate=2025-04-10`）；
2. IAM 中台接收并校验签名与时间戳，写入事件队列（Kafka）；
3. 离职工作流引擎触发：
   - 调用 AD PowerShell 模块执行 `Disable-ADAccount -Identity $uid`；
   - 调用 Microsoft Graph API 执行 `PATCH /users/{id} → accountEnabled=false`；
   - 调用邮箱网关 API 设置 `MailboxState=Disabled` 并关闭 POP/IMAP/SMTP；
   - 向 Okta 同步禁用指令，由 Okta 向下游 SaaS 应用广播注销事件；
4. 发送告警至 IT 运维群（企微/钉钉）：“【ALM-ALERT】账号 `zhang.san` 已于 2025-04-10 10:23:15 自动停用”；
5. 启动 30 天倒计时定时任务，到期前 3 天邮件提醒 IT 安全组复核。

> ⚠️ **常见错误码与处理**  
> - `ERR_ALM_409`：AD 账号已存在但邮箱冲突 → 检查历史重名记录，启用 `zhang.san2@company.com` 并通知 HR 更新入职信息；  
> - `ERR_ALM_503`：Graph API 限流 → 启用指数退避重试（最多 3 次），失败后转入人工工单队列；  
> - `ERR_ALM_404`：SaaS 应用账号不存在 → 记录为“未纳管账号”，推送至账号治理看板待清理。

## 合规与审计要求

- 所有账号操作必须留痕：包括操作人（系统账号 or 人工账号）、时间、原始事件 payload（脱敏后）、执行结果；
- 每月生成《账号生命周期执行质量报告》，含：开通及时率、停用 SLA 达成率、权限残留数、异常中断次数；
- 每季度执行账号权限一致性巡检（比对 HRIS 组织架构 vs AD 组成员 vs 邮箱通讯组）；
- 符合等保 2.0 第三级“身份鉴别”与“访问控制”条款，以及 ISO/IEC 27001 A.9.2.3 权限管理要求。
