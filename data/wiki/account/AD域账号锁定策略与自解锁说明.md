# AD域账号锁定策略与自解锁说明

## 一、概述  
本说明适用于公司统一使用的 Active Directory（AD）域环境，旨在规范域账号因多次输入错误密码导致的锁定行为，并明确自动解锁机制、人工干预方式及预防建议。所有员工应了解并遵守相关策略，以保障账号安全与业务连续性。

## 二、账号锁定触发条件  

### 2.1 锁定阈值  
AD域默认配置如下（由域控制器组策略统一管理）：

| 策略项 | 配置值 | 说明 |
|--------|--------|------|
| 账号锁定阈值 | **5 次无效登录尝试** | 连续失败达此次数即触发锁定 |
| 账号锁定时间 | **30 分钟** | 锁定后自动解锁的等待时长（可配置） |
| 重置账户锁定计数器 | **30 分钟** | 自最后一次失败登录起，若未再发生失败，则计数器清零 |

> ⚠️ 注意：上述值为公司当前生产环境标准配置，具体以 `Group Policy Management Console (GPMC)` 中 `Default Domain Policy` 或所属OU的链接策略为准。

### 2.2 触发场景示例  
以下操作均会计入失败登录次数：
- Windows 登录界面输入错误密码  
- Outlook / OWA 使用错误凭据连接 Exchange  
- 映射网络驱动器时提供错误域账号密码  
- 第三方应用（如VPN客户端、Citrix Workspace）调用AD认证失败  
- 已过期设备（如未同步时间的笔记本）因Kerberos时间偏移导致认证拒绝（可能误判为密码错误）

## 三、自解锁机制说明  

### 3.1 自动解锁流程  
当满足以下全部条件时，账号将在锁定期满后**自动恢复可用**，无需管理员介入：

1. 账号被标记为 `Locked Out`（可通过 `Active Directory Users and Computers` 查看属性中的「帐户」选项卡确认）  
2. 自首次锁定起已持续经过设定的「账号锁定时间」（当前为30分钟）  
3. 期间无新增失败登录尝试（否则计时重启）  

### 3.2 自解锁验证方式  
用户可按以下步骤确认是否已解锁：
1. 在任意域加入设备上打开「运行」（Win+R），输入 `cmd` 打开命令提示符  
2. 执行以下命令检查账号状态（需替换 `<username>`）：
   ```shell
   net user <username> /domain | findstr /i "account active"
   ```
   - 若返回含 `Account active: Yes`，表示已解锁；  
   - 若返回 `Account active: No` 或提示 `The user name could not be found`，请等待或联系IT支持。

## 四、人工解锁操作（仅限IT支持人员）  

> 🔐 权限要求：需具备 `Domain Admins` 或经授权的 `HelpDesk Operators` 组成员身份

### 4.1 解锁步骤（图形界面）  
1. 打开 **Active Directory Users and Computers**（ADUC）  
2. 定位至对应用户对象 → 右键 → 选择 **“重置账户”**（Reset Account）  
3. 勾选 **“解锁账户”**（Unlock account）→ 点击确定  
4. 建议同步执行密码重置（如用户遗忘密码），并提醒其启用多因素认证（MFA）

### 4.2 常见错误码参考  
| 错误码 | 含义 | 应对建议 |
|--------|------|-----------|
| `0x80070775` (`ERROR_ACCOUNT_LOCKED_OUT`) | 账号已被锁定 | 等待自解锁或人工解锁 |
| `0x80070776` (`ERROR_PASSWORD_MUST_CHANGE`) | 密码已过期且必须修改 | 引导用户通过自助密码重置门户操作 |
| `0x80070777` (`ERROR_PASSWORD_EXPIRED`) | 密码已过期 | 同上，或由管理员重置并勾选“用户下次登录时须更改密码” |

## 五、预防建议  

1. ✅ **启用自助密码重置（SSPR）服务**：员工可通过公司SSPR门户（https://password.company.com）在锁定前主动更新密码，避免因遗忘导致频繁锁定。  
2. ✅ **检查本地保存的凭据**：清理控制面板 → 「凭据管理器」中过期的Windows凭据、Git凭据等。  
3. ✅ **校准设备系统时间**：确保域内设备与域控制器时间偏差 ≤ 5 分钟（Kerberos要求），可执行 `w32tm /resync` 强制同步。  
4. ❌ **避免在多台设备/应用中重复使用错误密码**：尤其注意手机邮件客户端、Outlook桌面版、Teams等后台静默认证行为。
