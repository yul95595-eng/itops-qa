# 账号禁用与重新启用流程

> **适用范围**：公司所有正式员工、外包人员及临时访客账号（AD 域账号、企业邮箱、OA 系统、VPN 及 SSO 关联应用）  
> **责任主体**：IT 服务台（Service Desk）、IT 运维组、部门直属主管、HR 部门  
> **生效日期**：2024年7月1日  
> **文档版本**：v2.3  

---

## 一、触发条件

以下任一情形发生时，须立即启动账号禁用流程：

| 触发场景 | 说明 | 责任方 | SLA（时效） |
|----------|------|--------|-------------|
| 员工离职（含辞职、辞退、合同到期） | HR 在 eHR 系统提交「离职申请」并审批通过后自动触发 | HR | ≤ 15 分钟（系统自动） |
| 长期离岗（≥30个自然日） | 包括产假、病假、外派、借调等，需由部门主管在 OA 提交《账号冻结申请》 | 部门主管 | ≤ 2 个工作日 |
| 安全事件响应 | 如检测到异常登录、凭证泄露、MFA 绕过等高风险行为 | IT 安全组 | ≤ 5 分钟（紧急禁用） |
| 违规使用审计确认 | 经合规审计发现违规操作（如越权访问、批量导出敏感数据） | 合规与 IT 运维联合判定 | ≤ 1 个工作日 |

> ⚠️ 注：禁用操作**不删除账号**，仅停用认证能力（LDAP `userAccountControl` 标志位设为 `514`），保留全部历史数据与邮箱归档。

## 二、禁用操作流程（标准步骤）

### 1. 自动化禁用（推荐，适用于 HR 流程驱动场景）

1. HR 在 eHR 系统完成离职/离岗流程审批；
2. eHR 通过 Webhook 向 AD 同步状态（字段：`employeeStatus=Inactive`）；
3. IT 自动化平台（Ansible + PowerShell 模块）每 5 分钟轮询一次变更队列；
4. 匹配到目标账号后，执行以下操作：
   - 禁用 AD 账号（`Disable-ADAccount`）；
   - 清除 Kerberos TGT 缓存（`klist purge -li 0x3e7`）；
   - 设置邮箱转发至部门共享邮箱（PowerShell: `Set-Mailbox -ForwardingAddress "shared-dept@company.com"`）；
   - 在 Okta 中将账号状态置为 `SUSPENDED`（同步延迟 ≤ 90 秒）；
   - 记录操作日志至 SIEM（Syslog 格式，含操作人、时间戳、原始触发事件 ID）。

### 2. 手动禁用（适用于安全事件或流程未覆盖场景）

1. IT 运维人员登录 [AD 管理控制台](https://adadmin.company.internal)；
2. 使用精确匹配搜索目标账号（**禁止模糊搜索**，防止误操作）；
3. 右键 → 「禁用账户」→ 勾选：
   - ☑️ 立即终止所有活动会话（强制注销已登录终端）  
   - ☑️ 禁用所有 MFA 设备绑定（清除 Azure AD `StrongAuthenticationMethods`）  
   - ☑️ 同步禁用关联邮箱（Exchange Online：`Set-Mailbox -AccountDisabled $true`）  
4. 输入双因素认证（Duo Push + YubiKey）完成二次授权；
5. 在 ITSM 工单系统（Jira Service Management）中创建禁用记录（模板：`INC-SEC-<YYYYMMDD>-XXXXX`），注明原因、依据及审批截图。

## 三、重新启用流程

> ✅ **前提条件**：  
> - 账号仍存在于 AD（未被 `Remove-ADUser` 删除）；  
> - 重新启用申请已获直属主管 + IT 安全负责人双签审批；  
> - 原邮箱未被回收（保留期：禁用后 180 天）；  
> - 若涉及权限变更，须同步更新 RBAC 角色（参考《权限最小化配置规范 v4.1》）。

### 启用步骤（有序列表）

1. **审批验证**  
   - 登录 ITSM 系统，核验工单 `REQ-ENABLE-<ID>` 中的电子签名与审批链完整性；  
   - 检查是否附有 HR 出具的《返岗确认函》扫描件（PDF 签章版）。

2. **AD 账号启用**  
   - 执行 `Enable-ADAccount -Identity "CN=ZhangSan,OU=Users,DC=company,DC=local"`；  
   - 重置密码策略标志位（`Set-ADAccountPassword -Reset -NewPassword (ConvertTo-SecureString "TempPass@2024!" -AsPlainText -Force)`）；  
   - 强制用户首次登录时修改密码（`Set-ADUser -ChangePasswordAtLogon $true`）。

3. **邮箱与应用恢复**  
   - 解除 Exchange Online 邮箱禁用状态：`Set-Mailbox -Identity "zhangsan@company.com" -AccountDisabled $false`；  
   - 在 Okta 中将账号状态切回 `ACTIVE`，并触发 MFA 重新绑定引导；  
   - 检查 SharePoint/Teams 权限继承是否自动恢复（若失效，手动执行 `Update-SPUser` 或 Teams PowerShell `Grant-CsTeamsChannelsPolicy`）。

4. **通知与验证**  
   - 自动向用户发送启用成功邮件（含新密码临时链接、MFA 设置指引、密码策略说明）；  
   - 由 IT 服务台在 2 小时内致电用户确认登录与核心业务系统（OA/ERP/邮箱）可用性；  
   - 工单闭环前，上传验证截图至 ITSM 附件区（含 Outlook Web 登录成功界面、OA 首页加载截图）。

## 四、常见问题与错误码

| 错误现象 | 可能原因 | 解决方案 |
|----------|----------|-----------|
| 启用后无法登录 Outlook Web | Exchange Online 邮箱仍处于 `AccountDisabled` 状态 | 运行 `Get-Mailbox username@company.com \| fl AccountDisabled`，若为 `True` 则执行 `Set-Mailbox -AccountDisabled $false` |
| Okta 显示“User suspended”但 AD 已启用 | Okta SCIM 同步延迟或断连 | 检查 Okta Admin Console → Directory → SCIM Logs；手动触发 `Sync Now`；如失败则提交 Okta Support Ticket（含 Event ID） |
| 首次登录提示“密码已过期”但未触发修改流程 | `ChangePasswordAtLogon` 属性未正确设置 | 使用 ADSI Edit 检查 `pwdLastSet = 0`，或重新执行 `Set-ADUser -ChangePasswordAtLogon $true` |
| Teams 频道访问 403 | 用户未分配 Teams 许可证或策略未同步 | 运行 `Get-AzureADUserLicenseDetail -ObjectId <UPN>`；若缺失，则分配 `Microsoft 365 E3` 许可并等待 15 分钟策略生效 |

## 五、审计与合规要求

- 所有禁用/启用操作必须留痕，日志保存 ≥ 365 天（符合 ISO 27001 A.9.4.2 & 等保 2.0 8.1.4）；  
- 每季度由 IT 审计组抽样检查 5% 的启用工单，验证审批完整性与操作合规性；  
- 禁用账号的邮箱归档数据按《数据保留策略》自动转存至 WORM 存储（不可删改，保留期：7 年）。
