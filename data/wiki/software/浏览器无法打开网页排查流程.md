# 浏览器无法打开网页排查流程

> **适用对象**：公司IT支持人员、一线运维工程师、桌面技术支持  
> **更新日期**：2024-06-15  
> **知识域**：软件与报错  

---

## 一、快速定位原则（5分钟黄金判断法）

在接到“浏览器打不开网页”报障后，优先执行以下三步快速收敛问题范围：

1. **确认是否全局失效**：尝试访问多个不同域名（如 `https://www.baidu.com`、`https://www.github.com`、公司内部系统URL）  
2. **交叉验证终端**：同一网络下其他设备（手机/另一台电脑）能否正常访问？  
3. **检查基础连通性**：  
   - 打开命令提示符（Windows）或终端（macOS/Linux），执行：  
     ```bash
     ping -c 4 8.8.8.8      # 测试基础IP连通性
     ping -c 4 www.baidu.com # 测试DNS解析+连通性
     ```

> ✅ 若 `ping 8.8.8.8` 成功但 `ping www.baidu.com` 失败 → **DNS解析异常**  
> ❌ 若两者均失败 → **网络连接层故障（网卡、网关、代理、防火墙等）**

---

## 二、分层排查路径（OSI模型逐层递进）

### ### 1. 物理与链路层（L1–L2）
- 检查网线/无线连接状态图标（是否显示“已连接”且无感叹号）  
- 重启网络适配器：  
  - Windows：`控制面板 > 网络和 Internet > 网络连接 > 右键禁用→启用`  
  - macOS：`系统设置 > 网络 > Wi-Fi/以太网 → 切换开关`  
- 查看IP配置：  
  ```bash
  ipconfig /all    # Windows
  ifconfig         # macOS/Linux（或使用 `ip a`）
  ```
  ✅ 正常应获取到有效IPv4地址（非 `169.254.x.x` 或 `0.0.0.0`）  
  ❌ 出现 `169.254.x.x` → DHCP失败，需检查路由器/DHCP服务或手动配置IP

### ### 2. 网络层（L3）与路由
- 执行路由跟踪定位中断点：  
  ```bash
  tracert www.baidu.com     # Windows
  traceroute www.baidu.com  # macOS/Linux
  ```
- 关键观察点：  
  - 前3跳是否可达（本地网关、出口路由器）  
  - 是否在某跳后持续 `* * * Request timed out`  
  - 是否出现 `Destination host unreachable`（目标不可达）或 `TTL expired in transit`（环路）

### ### 3. 传输层（L4）与代理/防火墙
| 检查项 | 操作方式 | 常见表现 |
|--------|----------|-----------|
| **系统代理设置** | Windows：`设置 > 网络和 Internet > 代理`；macOS：`系统设置 > 网络 > 高级 > 代理` | 错误启用「自动检测设置」或手动配置了不可用代理服务器（如 `127.0.0.1:8080`） |
| **安全软件拦截** | 临时禁用杀毒软件（如360、火绒）、企业EDR客户端 | 浏览器进程被阻止出网，日志中可见 `BLOCKED_BY_SECURITY_SOFTWARE` |
| **本地防火墙策略** | `Windows Defender 防火墙 > 高级设置 > 出站规则` | 存在拒绝 `chrome.exe` / `msedge.exe` 的规则 |

### ### 4. 应用层（L7）——浏览器专项诊断
#### ▶ 浏览器自身状态检查（按优先级排序）：
1. **清除缓存与Cookie**（推荐首选）  
   - Chrome/Edge：`Ctrl+Shift+Del` → 勾选「缓存的图像和文件」「Cookie及其他网站数据」→ 时间范围选「所有时间」  
2. **禁用所有扩展程序**  
   - 地址栏输入 `chrome://extensions` → 关闭全部开关 → 重启浏览器测试  
3. **重置浏览器设置**  
   - Chrome：`chrome://settings/reset` → 「将设置恢复为原始默认值」  
   - Edge：`edge://settings/reset` → 「将设置恢复为默认值」  
4. **检查HTTPS证书错误**  
   - 若仅 HTTPS 网站失败，访问时出现 `NET::ERR_CERT_DATE_INVALID` 或 `ERR_SSL_PROTOCOL_ERROR`：  
     - 校准系统时间（误差 > 3 分钟将导致证书校验失败）  
     - 清除系统证书存储（Windows：`certmgr.msc` → 删除异常根证书）  

#### ▶ 常见HTTP错误码速查表：
| 错误码 | 含义 | 典型原因 | 应对建议 |
|--------|------|-----------|------------|
| `ERR_CONNECTION_TIMED_OUT` | 连接超时 | 目标服务器宕机、中间网络阻断、本地防火墙拦截 | `telnet <domain> 443` 测试端口连通性 |
| `ERR_NAME_NOT_RESOLVED` | DNS解析失败 | 本地hosts劫持、DNS服务器不可用、域名拼写错误 | `nslookup www.baidu.com 8.8.8.8` 强制指定DNS查询 |
| `ERR_PROXY_CONNECTION_FAILED` | 代理连接失败 | 代理服务器地址错误、代理服务未运行、认证失败 | 检查代理配置，或切换为「不使用代理」 |
| `ERR_ADDRESS_UNREACHABLE` | 地址不可达 | 本地路由异常、IPv6优先导致兼容问题 | 在浏览器地址栏输入 `chrome://flags/#enable-ipv6` → 禁用IPv6尝试 |

## 三、高级排查工具推荐

| 工具 | 用途 | 使用方式 |
|------|------|-----------|
| **Wireshark** | 抓包分析TCP三次握手、DNS请求、TLS协商过程 | 过滤条件示例：<br>`http or dns or tcp.port == 443` |
| **curl（命令行）** | 绕过浏览器，验证底层HTTP可达性 | `curl -v https://www.baidu.com`（显示完整请求响应头） |
| **Browser Console（F12）** | 查看JS错误、资源加载失败、CSP拦截 | Network标签页 → 查看Status列及Failed原因 |
| **公司统一终端检测脚本** | 自动化执行上述10项检查并生成报告 | 运行 `diag_net_browser.bat`（Windows）或 `./diag_net_browser.sh`（macOS/Linux） |

## 四、典型场景速查（附解决方案）

| 场景 | 表象 | 根因 | 解决方案 |
|------|------|------|-----------|
| **仅Chrome无法打开，Edge正常** | Chrome白屏/ERR_CONNECTION_REFUSED | Chrome沙箱冲突或用户配置损坏 | 新建Chrome用户配置：`chrome.exe --user-data-dir="C:\temp\chrome_test"` |
| **公司内网系统可访问，外网全部失败** | `www.baidu.com` 显示“无法访问此网站” | 企业上网行为管理策略限制（如URL过滤、SSL解密拦截） | 联系网络安全部门确认策略组、检查是否启用「HTTPS透明代理」 |
| **重启后首次能打开，数分钟后复现** | 初次访问正常，后续频繁超时 | DNS缓存中毒或本地hosts被篡改 | `ipconfig /flushdns` + 检查 `C:\Windows\System32\drivers\etc\hosts` 文件内容 |
| **移动热点下正常，公司WiFi下失败** | 同一台设备切换网络即生效 | 公司WLAN认证页面未弹出（Captive Portal未触发） | 手动访问 `http://connectivitycheck.gstatic.com/generate_204` 触发认证 |
