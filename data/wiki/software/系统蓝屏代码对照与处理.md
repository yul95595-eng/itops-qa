# 系统蓝屏代码对照与处理（Windows）

> 本文档适用于公司内部 Windows Server 2016/2019/2022 及 Windows 10/11 桌面环境的蓝屏（BSOD）故障快速定位与处置，依据微软官方文档及生产环境高频案例整理。

## 常见蓝屏错误代码速查表

| 错误代码（STOP Code） | 中文含义 | 高频诱因 | 推荐优先级 |
|------------------------|-----------|------------|--------------|
| `0x0000007B (INACCESSIBLE_BOOT_DEVICE)` | 启动设备不可访问 | 存储驱动异常、SATA模式切换（AHCI ↔ IDE）、系统盘损坏 | ⚠️ 紧急（无法启动） |
| `0x0000001A (MEMORY_MANAGEMENT)` | 内存管理异常 | 物理内存故障、驱动内存越界、Pagefile.sys 损坏 | 🔴 高 |
| `0x0000003B (SYSTEM_SERVICE_EXCEPTION)` | 系统服务异常 | 第三方驱动（尤其显卡/杀毒/虚拟化）、NTDLL.dll 冲突 | 🟡 中高 |
| `0x000000D1 (DRIVER_IRQL_NOT_LESS_OR_EQUAL)` | 驱动 IRQL 不匹配 | 驱动尝试在不恰当的中断级别访问内存（常见于网卡/USB/声卡驱动） | 🔴 高 |
| `0x000000EF (CRITICAL_PROCESS_DIED)` | 关键系统进程终止 | svchost.exe / wininit.exe 异常退出、恶意软件劫持、系统文件损坏 | 🔴 高 |
| `0x000000FC (ATTEMPTED_EXECUTE_OF_NOEXECUTE_MEMORY)` | 尝试执行不可执行内存 | 缓冲区溢出攻击、驱动/应用未适配 DEP/NX 保护 | 🟡 中 |

> 💡 提示：蓝屏界面底部通常显示 STOP Code（如 `IRQL_NOT_LESS_OR_EQUAL`）及参数（如 `0x000000000000000A`），结合 `minidump` 文件（默认位于 `%SystemRoot%\Minidump\*.dmp`）可精准定位模块。

## 蓝屏根因分析与处置流程

### 1. 快速现场响应（首次蓝屏后立即执行）

1. **记录关键信息**  
   - 拍摄蓝屏全屏照片（含 STOP Code、4个参数、失败模块名，如 `dxgkrnl.sys`）；  
   - 记录蓝屏发生前操作（如安装驱动、更新 Windows、运行某软件）；  
   - 查看事件查看器 → Windows 日志 → 系统，筛选 `Error` 级别事件，重点关注来源为 `BugCheck` 或 `Kernel-Power` 的条目。

2. **安全模式验证**  
   - 强制重启 3 次触发自动修复 → 进入「疑难解答」→「高级选项」→「启动设置」→ 重启后按 `F4` 进入安全模式；  
   - 若安全模式可稳定运行 → 判定为**第三方驱动或软件冲突**；  
   - 若安全模式仍蓝屏 → 聚焦**硬件故障或系统核心损坏**。

### 2. 根因定位方法（根据响应结果选择）

#### ▶ 场景一：安全模式正常 → 驱动/软件冲突排查
- 使用 `msconfig` → 「服务」页 → 勾选「隐藏所有 Microsoft 服务」→ 禁用全部 → 重启；若正常，则逐批启用定位；  
- 执行 `driverquery /v > drivers.txt` 导出驱动清单，重点检查 `Date` 较新或 `Publisher` 非 Microsoft 的驱动；  
- 使用 [BlueScreenView](https://www.nirsoft.net/utils/blue_screen_view.html)（便携版）加载 `C:\Windows\Minidump\*.dmp`，按 `Crash Address` 排序，定位红色高亮的非系统驱动模块。

#### ▶ 场景二：安全模式异常 → 硬件/系统级诊断
- 运行内存诊断：Win+R → `mdsched.exe` → 选择「立即重新启动并检查问题」；  
- 检查磁盘健康：管理员 CMD 执行  
  ```cmd
  chkdsk C: /f /r
  wmic diskdrive get status,model,serialnumber
  ```
- 验证系统文件完整性：  
  ```cmd
  sfc /scannow
  dism /online /cleanup-image /restorehealth
  ```

### 3. 典型错误代码处置方案

| STOP Code | 推荐操作 | 注意事项 |
|-----------|----------|----------|
| `0x7B` | 进入 BIOS 将 SATA Mode 改为与原系统一致（通常为 AHCI）；使用 `bootrec /rebuildbcd` 重建启动项 | 切勿在已安装系统上随意切换 RAID/AHCI 模式 |
| `0x1A` | 替换内存条测试；禁用内存超频；检查 `PoolMon` 工具定位内存泄漏驱动 | `0x1A` 参数 `0x0000000000000002` 多指向物理内存故障 |
| `0xD1` | 卸载最近安装的驱动（尤其是 `xxx.sys` 文件）；使用 `verifier.exe` 启用驱动验证器（仅限测试环境） | `verifier` 可能导致启动变慢或额外蓝屏，需谨慎启用 |

## 附录：关键工具与命令速查

- **Dump 分析工具链**：  
  - [Windows SDK Debugging Tools](https://developer.microsoft.com/en-us/windows/downloads/windows-sdk/)（含 WinDbg Preview）  
  - 分析命令示例（WinDbg）：  
    ```text
    !analyze -v      // 自动分析当前 dump
    lm t n           // 列出已加载模块及时间戳
    !drvobj <driver_name> 4  // 查看驱动对象详情
    ```

- **日志关联命令**：  
  ```cmd
  wevtutil qe System /q:"*[System[(EventID=41) or (EventID=1001)]]" /f:text  // 查询意外关机/蓝屏事件
  ```

> ✅ **运维建议**：  
> - 所有服务器应启用「小内存转储」（Small Memory Dump），确保 `C:\Windows\Minidump\` 目录有至少 500MB 可用空间；  
> - 生产环境部署前，强制对驱动进行 [HLK（Hardware Lab Kit）认证](https://learn.microsoft.com/en-us/windows-hardware/test/hlk/)；  
> - 定期执行 `sfc /scannow + DISM` 维护，纳入自动化巡检脚本。
