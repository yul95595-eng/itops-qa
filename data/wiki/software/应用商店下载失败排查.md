# 应用商店下载失败排查指南

## 一、常见现象与初步定位

当用户在公司统一应用商店（内部 AppStore）中点击「下载」或「更新」按钮后，出现以下任一情况，即视为下载失败：

- 按钮状态卡在「下载中…」但进度条长期无变化（>2分钟）  
- 立即弹出错误提示（如：“下载失败”、“网络异常”、“签名验证失败”）  
- 下载完成后安装包无法打开，提示“此应用未经过安全认证”或“包损坏”  
- 日志中出现 `ERR_DOWNLOAD_FAILED`、`ERR_CERT_INVALID`、`ERR_APK_SIGNATURE_MISMATCH` 等错误码  

> ✅ **建议第一步**：确认设备已接入公司内网（Wi-Fi 或有线），且未启用第三方代理/VPN。

---

## 二、分层排查流程

### 2.1 网络层检查

| 检查项 | 操作命令/方式 | 预期结果 | 异常说明 |
|--------|----------------|------------|-------------|
| DNS 解析 | `nslookup appstore.internal.corp`（Windows/Linux/macOS） | 返回有效内网 IP（如 `10.20.30.40`） | 若返回 `NXDOMAIN` 或超时 → DNS 配置错误或域名未发布 |
| 连通性测试 | `ping -c 4 appstore.internal.corp`（Linux/macOS）<br>`ping -n 4 appstore.internal.corp`（Windows） | 丢包率 0%，延迟 <50ms | 高丢包/超时 → 网络策略拦截（如防火墙、ACL）、路由异常 |
| HTTPS 可达性 | `curl -I https://appstore.internal.corp/api/v1/download?pkg=com.example.app` | 返回 `HTTP/2 200` 或 `302` | 返回 `403 Forbidden` → 认证 Token 过期；`502 Bad Gateway` → 后端服务异常 |

### 2.2 客户端配置检查

1. **确认应用商店客户端版本**  
   - 进入「设置 → 关于应用商店」，核对版本号 ≥ `v3.8.2`（旧版本存在 TLS 1.2 兼容性缺陷）  
   - 若低于该版本，请通过 [内部 OTA 更新页](https://ota.internal.corp/appstore) 手动升级  

2. **检查证书信任链**  
   - Android 设备：进入「设置 → 安全 → 加密与凭据 → 信任的凭据」→ 查看是否启用 `COMPANY-INTERNAL-CA-2023`  
   - iOS 设备：需提前安装并「信任」公司 MDM 推送的根证书（路径：设置 → 已下载描述文件 → 点击安装 → 设置 → 通用 → 关于本机 → 证书信任设置）  

3. **清除本地缓存与临时文件**  
   - Android：设置 → 应用 → 应用商店 → 存储 → 「清除缓存」+「清除数据」（⚠️ 注意：清除数据将退出登录）  
   - Windows/macOS 客户端：菜单栏 → 帮助 → 「重置下载队列」+ 「刷新本地索引」  

### 2.3 服务端与策略侧核查

| 维度 | 检查点 | 排查方式 | 责任方 |
|------|---------|------------|----------|
| 应用上架状态 | 目标 APK/IPA 是否处于「已发布」且「生效中」 | 登录 [应用管理后台](https://admin.appstore.internal.corp) → 搜索包名 → 查看「发布状态」与「生效时间」 | 应用发布组 |
| 权限策略 | 当前用户所属部门是否被授权访问该应用 | 后台 → 应用详情页 → 「访问控制」标签页 → 检查用户组/OU 匹配 | IAM 运维组 |
| 签名一致性 | APK 签名哈希是否与后台登记一致 | 后台 → 应用详情 → 「签名摘要」字段；对比本地执行：<br>`keytool -printcert -jarfile app-release.apk \| grep "SHA256"` | 安全合规组 |

## 三、典型错误码速查表

| 错误码 | 含义 | 推荐操作 |
|--------|------|-----------|
| `ERR_DOWNLOAD_TIMEOUT` | CDN 节点响应超时（>90s） | 切换至备用下载源（设置 → 高级 → 启用「直连模式」） |
| `ERR_VERIFICATION_FAILED` | APK 签名校验失败（签名变更未同步） | 联系应用负责人重新上传签名一致的包，并触发「强制重签」流程 |
| `ERR_LICENSE_EXPIRED` | 用户 License 已过期或未分配 | 在 [License 管理系统](https://license.internal.corp) 中续期或申请权限 |
| `ERR_STORAGE_FULL` | 设备剩余存储 <500MB（强制阈值） | 清理临时文件或扩展存储空间后重试 |

## 四、附：快速自检清单（供一线支持使用）

1. ✅ 用户是否处于公司内网环境？（非访客网络、非4G热点）  
2. ✅ 设备时间是否准确？（误差 >3分钟 将导致 JWT Token 验证失败）  
3. ✅ 应用商店客户端是否为最新版？（v3.8.2+）  
4. ✅ 是否已安装并信任 `COMPANY-INTERNAL-CA-2023` 根证书？  
5. ✅ 目标应用在后台显示「发布状态=已发布」且「生效时间 ≤ 当前时间」？  
6. ✅ 用户账号是否归属该应用所配置的 OU 或用户组？  

> 🔁 若以上均满足仍失败，请收集以下信息提交至 IT 服务台：  
> - 设备型号 + OS 版本  
> - 应用商店版本号  
> - 完整错误截图（含时间戳）  
> - `adb logcat | grep -i "appstore\|download"`（Android）或 Console 日志过滤关键词（macOS/iOS）
