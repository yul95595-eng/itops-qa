# 文件共享权限与访问异常

## 概述  
在公司内部文件共享（如 Windows Server 文件服务器、Samba 共享、NAS 设备或云盘协同平台）场景中，用户常因权限配置不当、身份验证失败或协议兼容性问题，导致「拒绝访问」、「无法连接」、「无权查看/修改」等异常。本文档系统梳理常见原因、诊断流程及修复方案，适用于 IT 运维人员与终端用户自查参考。

---

## 常见错误现象与对应错误码

| 错误提示 | 典型错误码/日志线索 | 可能原因 |
|----------|---------------------|----------|
| `0x80070005 - 拒绝访问` | Windows 事件日志：`Event ID 1202`（SMB 访问被拒绝） | 共享权限 + NTFS 权限双重限制未满足；用户不在授权组；UAC 虚拟化干扰 |
| `Connection refused` / `No route to host` | `netstat -an \| findstr :445` 无监听 | SMB 服务未启用；防火墙（Windows Defender 防火墙 / iptables）拦截 445 端口 |
| `Permission denied (publickey)` | SSH/SFTP 日志中出现 | 密钥认证失败；`authorized_keys` 权限过宽（如 `644`，应为 `600`）；SSH 服务未启用 `PubkeyAuthentication yes` |
| `NT_STATUS_ACCESS_DENIED` | Samba 日志 `/var/log/samba/log.smbd` | `valid users` 或 `write list` 配置错误；SELinux 强制策略阻止访问（`ls -Z` 查看上下文） |
| `The network path was not found` | `ping <server>` 成功但 `net use Z: \\server\share` 失败 | DNS 解析失败；NetBIOS 名称解析异常（WINS 未配置或 `lmhosts` 缺失）；SMBv1 被禁用但客户端仅支持 SMBv1 |

## 权限模型核心原则（以 Windows SMB 为例）

文件共享访问需**同时满足两层权限检查**：

### 1. 共享权限（Share Permissions）  
- 控制**网络层访问**（即能否连接到共享路径 `\\server\share`）  
- 仅三种级别：`读取`、`更改`、`完全控制`  
- **不继承**，不作用于本地登录用户  

### 2. NTFS 权限（Security Permissions）  
- 控制**文件系统级操作**（打开、编辑、删除等）  
- 支持精细粒度（如“创建文件/写入数据”、“删除子文件夹及文件”）  
- 遵循**最小权限原则**，且**拒绝权限优先于允许权限**  

> ✅ 正确实践：共享权限设为 `读取` 或 `更改`（宽松），NTFS 权限严格按角色分配（如 `Domain\Finance-Group: 修改` + `Domain\Audit-Group: 读取`）

## 排查与修复流程（标准 SOP）

### 步骤 1：基础连通性验证  
1. 使用 `ping <服务器主机名/IP>` 确认网络可达  
2. 执行 `telnet <服务器IP> 445`（Windows）或 `nc -zv <IP> 445`（Linux）测试 SMB 端口开放  
3. 若失败 → 检查目标服务器 SMB 服务状态（`Get-Service LanmanServer` / `systemctl status smb`）及防火墙规则  

### 步骤 2：身份与认证确认  
1. 在客户端执行 `whoami /groups`（Windows）或 `id`（Linux/macOS）确认当前用户 SID/UID 及所属组  
2. 核对服务器端共享配置中 `valid users`（Samba）或「共享权限」中是否包含该用户或其所在组  
3. 若使用域账户，运行 `klist` 检查 Kerberos 票据有效性；必要时执行 `kinit username@DOMAIN.COM`  

### 步骤 3：权限叠加分析（关键！）  
1. 在服务器上右键共享文件夹 → **属性 → 安全选项卡** → 点击「高级」→「有效访问」→ 输入用户 → 查看**最终计算出的允许/拒绝项**  
2. 同步检查「共享选项卡」→ 「高级共享」→ 「权限」设置  
3. 注意：若任一层含 `拒绝` 条目（尤其 `Everyone: 拒绝`），将直接阻断访问  

### 步骤 4：协议与兼容性检查  
- Windows 客户端：运行 `Get-SmbClientConfiguration`，确认 `RequireSecuritySignature` 和 `EnableSMB1Protocol` 是否符合服务端要求  
- Linux Samba 客户端：检查 `/etc/samba/smb.conf` 中 `client min protocol = SMB2` 是否与服务端匹配  
- 禁用 SMBv1（高危）：PowerShell 执行 `Set-SmbServerConfiguration -EnableSMB1Protocol $false -Confirm:$false`  

### 步骤 5：日志定向分析  
| 平台 | 日志位置 | 关键过滤关键词 |
|------|-----------|----------------|
| Windows Server | `事件查看器 → Windows 日志 → 安全` | `4625`（登录失败）、`5145`（对象访问被拒） |
| Samba（Linux） | `/var/log/samba/log.smbd` | `connect`, `access denied`, `session setup failed` |
| NetApp ONTAP | `system log show -message "permission"` | `NFS: Access denied`, `CIFS: No permissions` |

## 典型修复案例

### ▶ 场景：新入职员工无法访问部门共享盘  
- **现象**：映射 `\\fileserver\hr` 提示 `0x80070005`  
- **排查发现**：  
  - 用户已加入 `Domain\HR-Staff` 组  
  - 共享权限中 `HR-Staff` 组具有 `更改` 权限 ✅  
  - NTFS 权限中 `HR-Staff` 组仅被赋予 `读取 & 执行` ❌（遗漏“写入”）  
- **修复**：在 NTFS 安全设置中为 `HR-Staff` 添加 `修改` 权限，并勾选「替换所有子对象权限条目」  

### ▶ 场景：Linux 客户端挂载 Samba 报 `NT_STATUS_LOGON_FAILURE`  
- **根因**：Samba 服务端启用了 `map to guest = bad user`，但客户端传递了空密码；实际应配置 `guest ok = yes` 并确保共享目录 SELinux 上下文为 `samba_share_t`  
- **修复命令**：  
  ```bash
  sudo semanage fcontext -a -t samba_share_t "/srv/shared(/.*)?"
  sudo restorecon -Rv /srv/shared
  ```

## 附录：快速检测脚本（Windows PowerShell）

```powershell
# 检查本地 SMB 服务与防火墙状态
Write-Host "[1] SMB Server Status:" -ForegroundColor Green
Get-Service LanmanServer | Select-Object Name,Status,StartType

Write-Host "`n[2] Firewall Rule for SMB:" -ForegroundColor Green
Get-NetFirewallRule -DisplayName "*File and Printer Sharing*" | 
  Where-Object {$_.Enabled -eq 'True'} | 
  Select-Object DisplayName,Enabled,Profile

Write-Host "`n[3] Effective Permissions for Current User on \\server\share:" -ForegroundColor Green
icacls "\\server\share" /user "$env:USERDOMAIN\$env:USERNAME" /t /c 2>$null | Out-String
```

> ⚠️ 注意：执行前需以管理员身份运行；`/t` 参数递归检查子项，`/c` 忽略错误继续。
