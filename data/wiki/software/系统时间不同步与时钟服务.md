# 系统时间不同步与时钟服务（NTP/Chrony）

## 概述  
系统时间不同步是企业 IT 环境中常见但易被忽视的问题，可能导致以下严重后果：  
- 分布式系统日志时间戳错乱，影响故障排查；  
- TLS/SSL 证书校验失败（`CERTIFICATE_VERIFY_FAILED` 或 `NotValidAfter` 错误）；  
- 数据库主从复制延迟或中断（如 MySQL GTID、PostgreSQL 流复制）；  
- 定时任务（cron）执行异常或跳过；  
- Kubernetes 节点健康检查失败（`NodeNotReady` 因 kubelet 时间偏差 >1s）；  
- 安全审计日志（如 auditd、SIEM 接入）时间线失真。

Linux 系统主要依赖两类时钟同步服务：**NTP（Network Time Protocol）** 和更现代的 **Chrony**（推荐用于虚拟化/云环境）。二者均通过与上游 NTP 服务器通信，动态校准系统时钟（硬件时钟 RTC + 内核时钟）。

---

## 常见现象与错误码

| 现象 | 典型日志/命令输出 | 可能原因 |
|------|-------------------|----------|
| `systemctl status chronyd` 显示 `inactive (dead)` | `● chronyd.service - NTP client/server`<br>`Loaded: loaded (/usr/lib/systemd/system/chronyd.service; enabled; vendor preset: enabled)`<br>`Active: inactive (dead)` | 服务未启动、配置错误或端口被防火墙拦截（UDP 123） |
| `chronyc tracking` 显示 `Leap status : Not synchronised` | `Reference ID : 0.0.0.0 ()`<br>`Root distance : 0.000000000 s` | 无法连接上游服务器（网络不通、DNS 解析失败、上游不可用） |
| `timedatectl status` 中 `System clock synchronized: no` | `NTP service: active`<br>`RTC in local TZ: no` | 时钟未完成首次同步，或 `chronyd` 处于初始偏移收敛阶段（需等待数分钟） |
| `journalctl -u chronyd -n 50 --no-pager` 出现 `Invalid response from server` | `2024-06-12T10:23:45Z chronyd[1234]: Invalid response from 192.168.10.5` | 上游服务器返回非法 NTP 包（版本不兼容、防火墙篡改、中间设备干扰） |

> ⚠️ 注意：`timedatectl set-ntp true` 仅启用 systemd-timesyncd（轻量级客户端），**不替代 chronyd/NTPd**，且默认不支持 NTP 池轮询和复杂漂移补偿。

## 标准排查与修复流程

### 1. 确认当前时间状态
```bash
# 查看综合时间状态
timedatectl status

# 检查硬件时钟（RTC）与系统时钟是否一致
hwclock --show
date

# 验证时区设置（应为 Asia/Shanghai）
timedatectl show --property=Timezone --value
```

### 2. 检查并启用 Chrony 服务（推荐方案）
```bash
# 启动并设为开机自启
sudo systemctl enable --now chronyd

# 检查服务状态
sudo systemctl status chronyd

# 查看同步跟踪信息（关键字段：Last offset, RMS offset, Leap status）
sudo chronyc tracking

# 列出已配置的 NTP 源及同步状态
sudo chronyc sources -v
sudo chronyc sourcestats -v
```

### 3. 验证网络连通性与 NTP 端口
```bash
# 测试上游服务器 UDP 123 端口可达性（chrony 默认使用 123，非 80/443）
nc -uz pool.ntp.org 123  # 若超时，检查防火墙或代理策略

# 检查本机是否监听 UDP 123（仅当 chronyd 配置为 server 模式时需要）
sudo ss -uln | grep ':123'

# 临时关闭防火墙验证（生产环境慎用）
sudo firewall-cmd --remove-service=ntp --permanent && sudo firewall-cmd --reload
```

### 4. 检查 Chrony 配置（`/etc/chrony.conf`）
确保包含有效上游源（推荐国内可靠节点）：
```conf
# 替换默认 pool 行（避免国外节点延迟高/丢包）
pool ntp.aliyun.com iburst minpoll 4 maxpoll 10
pool ntp1.cloud.tencent.com iburst minpoll 4 maxpoll 10
pool time1.cloud.tencent.com iburst minpoll 4 maxpoll 10

# 必选参数
keyfile /etc/chrony.keys
driftfile /var/lib/chrony/drift
makestep 1.0 3  # 允许在首次同步时修正 >1s 的大偏差（3秒内生效）
rtcsync        # 将系统时钟同步到硬件时钟（每 11 分钟一次）
logdir /var/log/chrony
```
> ✅ 修改后执行：`sudo systemctl restart chronyd` 并等待 2–5 分钟观察 `chronyc tracking` 输出。

### 5. 强制手动同步（仅限紧急修复）
```bash
# 停止服务 → 手动校准 → 重启服务（避免 chronyd 拒绝大偏移）
sudo systemctl stop chronyd
sudo chronyd -q 'server ntp.aliyun.com iburst'
sudo systemctl start chronyd
```

## 进阶建议

- **虚拟机环境**：禁用 hypervisor 提供的「时间同步」（如 VMware Tools、QEMU Guest Agent 的时间同步功能），避免与 chronyd 冲突；
- **Kubernetes 节点**：在 `kubelet` 启动参数中添加 `--node-labels=node.kubernetes.io/time-sync=true`，并在监控中告警 `chronyc tracking | grep "Leap status"`；
- **审计合规**：定期导出 `chronyc tracking` 和 `chronyc sourcestats` 输出至日志中心，纳入 SOC 审计项；
- **备用机制**：对无外网的离线环境，部署局域网 NTP Server（如 `ntpd -g -x -c /etc/ntp.conf`），上游对接物理时钟或北斗授时模块。

✅ **验证成功标志**：  
`chronyc tracking` 中 `Leap status` 显示 `Normal`，`Last offset` 绝对值 < 0.1s，`RMS offset` < 0.2s，且 `timedatectl status` 显示 `System clock synchronized: yes`。
