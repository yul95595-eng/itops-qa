# 系统更新与补丁推送说明

> **适用对象**：IT 运维工程师、系统管理员、终端支持人员  
> **最后更新时间**：2024年10月15日  
> **文档版本**：v2.3  

---

## 一、概述

本说明文档规范公司内部操作系统（Windows Server / Linux RHEL/CentOS/Ubuntu）、核心业务中间件（Nginx、Tomcat、Oracle JDK）及自研平台组件的**例行更新与紧急补丁推送流程**，涵盖策略制定、测试验证、灰度发布、回滚机制及常见报错处置。

所有更新操作须严格遵循《公司IT变更管理流程》（CM-2023-001），禁止未经审批的生产环境直接升级。

---

## 二、更新类型定义

| 类型 | 触发条件 | 发布周期 | 审批要求 | 示例 |
|------|-----------|------------|-------------|------|
| **常规安全更新** | OS/软件厂商发布CVE修复补丁（CVSS ≥ 7.0） | 每月第二周周三凌晨 | 二级审批（运维主管 + 安全组） | `kernel-5.14.0-284.30.1.el9_2.x86_64.rpm`（RHEL9） |
| **功能增强更新** | 版本迭代含新特性或性能优化（非强制） | 季度一次，需配合业务窗口 | 三级审批（运维+开发+业务方） | `nginx-1.24.0-1.el9.x86_64.rpm`（支持QUIC v1） |
| **紧急热补丁（Hotfix）** | 生产环境出现P0级故障且官方未发布正式包 | 即时响应（≤2小时启动流程） | 临时战时审批（CTO授权） | `app-core-2.8.1-hotfix-20241012.jar`（修复JWT令牌解析空指针） |
| **兼容性更新** | 基础设施升级（如内核/驱动）引发依赖冲突 | 按需触发 | 同功能增强更新 | `nvidia-driver-535.129.03-1.el9.x86_64.rpm`（适配CUDA 12.3） |

## 三、标准推送流程（以Linux服务器为例）

### 3.1 预检与准备
1. 登录配置中心（Ansible Tower / 自研OpsPortal），筛选目标主机标签（如 `env=prod`, `role=api-gateway`）；
2. 执行预检脚本：  
   ```bash
   /opt/bin/update-precheck.sh --os-version=rhel9 --pkg-list="kernel,openssl,java-17-openjdk"
   ```
   ✅ 预期返回：`[OK] All dependencies satisfied`  
   ❌ 若报错 `ERROR: Conflicting package java-11-openjdk-headless-11.0.22.0.7-2.el9.x86_64 installed`，需先执行 `dnf remove java-11-openjdk-headless`；

### 3.2 分阶段推送
1. **灰度组（5%节点）**：自动部署并运行健康检查（HTTP 200 + `/actuator/health` JSON校验）；
2. **监控观察期（≥30分钟）**：确认无 `dmesg` 内核告警、`journalctl -u nginx --since "1 hour ago"` 无 `segmentation fault`；
3. **全量推送（剩余95%）**：通过Playbook设置 `--limit @/tmp/prod-batch2.yml` 分批次滚动更新；
4. **验证闭环**：调用自动化验收接口：  
   ```bash
   curl -s "https://ops-api.company.com/v1/patch/verify?host=api01&patch_id=RHEL9-KERNEL-284.30.1" | jq '.status'
   # 返回 "verified" 表示成功
   ```

## 四、常见报错与处置方案

| 错误现象 | 根本原因 | 解决步骤 | 关联错误码 |
|----------|-----------|------------|--------------|
| `yum update` 卡在 `Downloading packages...` 超过10分钟 | YUM源镜像同步延迟或网络ACL拦截 | ① 切换至内网镜像：`sed -i 's/mirrorlist/#mirrorlist/g; s|#baseurl=http://dl.rockylinux.org|baseurl=https://mirrors.company.internal|g' /etc/yum.repos.d/rocky.repo`<br>② 清理缓存：`dnf clean all && dnf makecache` | `ERR_CONNECTION_TIMED_OUT (curl)` |
| Tomcat启动失败，日志含 `java.lang.UnsupportedClassVersionError: Unsupported major.minor version 61.0` | 新JDK（17）编译的WAR包在旧JRE（11）运行 | ① 检查JAVA_HOME：`echo $JAVA_HOME`<br>② 统一升级JRE：`dnf install java-17-openjdk-headless -y`<br>③ 修改`/opt/tomcat/bin/setenv.sh`：`export JAVA_HOME=/usr/lib/jvm/java-17-openjdk` | `Java 61.0 = JDK 17` |
| 补丁安装后Nginx worker进程CPU持续100% | OpenSSL 3.0.7+ 与旧版PCRE2存在TLS handshake死循环 | 回退OpenSSL至3.0.2：`dnf downgrade openssl-3.0.2-15.el9_1.x86_64`，并重启服务 | `CVE-2023-0286`（已知冲突） |

## 五、回滚机制

- **自动回滚触发条件**：  
  - 灰度组健康检查失败率 > 20%；  
  - 全量推送中单节点启动超时 > 5分钟；  
  - Prometheus告警：`sum(rate(process_cpu_seconds_total{job="nginx"}[5m])) by (instance) > 0.9` 持续15分钟。  

- **手动回滚命令（RHEL/CentOS）**：  
  ```bash
  # 查看可回滚版本
  dnf history list | head -10
  # 回滚至上一事务（谨慎！）
  dnf history undo LAST
  # 强制重装旧包（指定版本）
  dnf install kernel-5.14.0-284.18.1.el9_2.x86_64 --allowerasing
  ```

> ⚠️ 注意：Windows Server 补丁回滚需通过 `wusa /uninstall /kb:XXXXXX` 或 DISM 命令，详见《Windows补丁管理细则》附录B。
