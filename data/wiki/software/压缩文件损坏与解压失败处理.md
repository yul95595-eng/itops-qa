# 压缩文件损坏与解压失败处理

> 本文档适用于公司内部 IT 运维、技术支持及开发人员，用于快速定位和修复常见压缩文件（ZIP、RAR、7z 等）损坏或解压失败问题。

---

## 一、常见现象与错误码识别

| 错误现象 | 典型错误提示（示例） | 可能原因 |
|----------|------------------------|-----------|
| 解压中断 | `Unexpected end of archive`（ZIP/RAR/7z） | 文件下载不完整、传输中断、存储介质损坏 |
| 校验失败 | `CRC failed`, `Data error`, `Invalid archive header` | 文件内容被篡改、磁盘写入错误、病毒修改 |
| 不支持格式 | `Cannot open file as archive`, `Unknown format` | 扩展名伪造（如 `.zip` 实际为文本）、格式不兼容（如 ZIP64 未启用） |
| 权限/路径异常 | `Permission denied`, `Path too long (Windows)`, `Operation not permitted (macOS)` | 目标目录无写权限、路径含非法字符、NTFS 路径超 260 字符限制 |

---

## 二、标准化排查与修复流程

### 步骤 1：验证文件完整性

1. **检查文件大小**  
   对比原始发布页/邮件附件声明的字节数（如 `v2.3.1-release.zip: 15,842,917 bytes`），使用命令行确认：
   ```bash
   # Linux/macOS
   ls -lh filename.zip
   # Windows（PowerShell）
   Get-Item .\filename.zip | Select-Object Length
   ```

2. **校验哈希值（如有提供）**  
   若官方提供 SHA256/MD5，执行校验：
   ```bash
   sha256sum filename.zip        # Linux/macOS
   certutil -hashfile filename.zip SHA256  # Windows
   ```

### 步骤 2：尝试多工具交叉解压

| 工具 | 适用场景 | 命令示例（CLI） |
|------|----------|-----------------|
| `7-Zip`（推荐） | 兼容性最强，支持修复 ZIP | `7z t filename.zip`（测试完整性）<br>`7z x filename.zip -o./output/`（解压） |
| `unzip`（Linux/macOS） | 快速验证 ZIP 标准合规性 | `unzip -t filename.zip`（测试）<br>`unzip -o filename.zip`（覆盖解压） |
| `WinRAR`（Windows GUI） | 提供“修复归档”功能（仅 ZIP/RAR） | 右键 → *“修复归档…”* → 指定输出路径 |

> ⚠️ 注意：`7z` 的 `t`（test）命令可检测 CRC 错误但**无法修复数据损坏**；仅对 ZIP 格式支持有限修复（需 `-r` 参数配合备份卷）。

### 步骤 3：高级恢复手段（仅限关键数据）

- **使用 `zip -F` / `zip -FF`（Linux/macOS）**  
  针对 ZIP 文件结构损坏（如中央目录丢失）：
  ```bash
  zip -F broken.zip --out repaired.zip   # 尝试修复（单卷）
  zip -FF broken.zip --out repaired.zip  # 强制修复（多卷/严重损坏）
  ```

- **提取可读文件（跳过损坏项）**  
  使用 `7z` 的 `-xr!` 排除已知损坏路径，或用 `unar`（macOS/Linux）：
  ```bash
  7z x archive.zip -o./recovered/ -y -xr!*.tmp  # 跳过临时文件
  unar -f archive.zip  # 自动跳过无法解压项，保留可用文件
  ```

- **十六进制分析（终极手段）**  
  若怀疑文件头损坏（如 ZIP 应以 `50 4B 03 04` 开头），用 `xxd` 或 `HxD` 检查前 16 字节：
  ```bash
  head -c 16 filename.zip | xxd
  # 正常 ZIP 头应显示：00000000: 504b 0304 ... 
  ```

## 三、预防建议

1. ✅ **下载阶段**：优先使用支持断点续传的工具（如 `curl -C -`, `wget -c`）；避免浏览器直接下载大文件。
2. ✅ **传输阶段**：内网分发使用 `rsync --checksum` 或 `sha256sum` 校验；跨网络使用 `scp` 替代 `ftp`。
3. ✅ **存储阶段**：定期对归档文件执行 `7z t` 批量健康检查（可集成至备份脚本）。
4. ❌ **禁止操作**：手动修改压缩包扩展名、用文本编辑器打开二进制压缩文件、在解压中强制关机。
