# 即时通讯软件登录异常排查指南

> 本文档适用于公司内部统一部署的即时通讯客户端（版本 ≥ v3.8.0），涵盖常见登录失败场景、诊断步骤及修复方案。

---

## 一、典型登录异常现象分类

| 异常表现 | 可能原因 | 优先级 |
|----------|-----------|---------|
| 输入账号密码后无响应，界面卡在“正在连接…” | 网络代理配置错误 / 客户端证书过期 | ⚠️ 高 |
| 提示「账号或密码错误」（但确认输入正确） | 多因素认证（MFA）未通过 / 密码策略强制更新未完成 | ⚠️ 高 |
| 登录弹窗反复闪退或崩溃 | 客户端本地缓存损坏 / .NET Runtime 环境缺失（Windows） | ⚠️ 中 |
| 显示 `ERR_CONNECTION_TIMED_OUT` 或 `ERR_SSL_VERSION_OR_CIPHER_MISMATCH` | TLS 1.2 未启用 / 企业防火墙拦截 `im-api.company.com:443` | ⚠️ 高 |
| 登录成功但收不到消息/联系人列表为空 | 同步服务未启动（`IMSyncService`） / 用户归属组织单元（OU）权限异常 | ⚠️ 中 |

---

## 二、标准化排查流程（按顺序执行）

### 步骤 1：基础连通性验证
1. 打开命令行（Windows：`Win+R` → `cmd`；macOS/Linux：终端）  
2. 执行以下检测：
   ```bash
   # 检查 DNS 解析
   nslookup im-api.company.com

   # 测试 HTTPS 端口连通性（超时阈值 ≤ 3s）
   telnet im-api.company.com 443  # Windows 需先启用 Telnet 客户端功能
   # 或使用 PowerShell（推荐）
   Test-NetConnection im-api.company.com -Port 443

   # 验证 TLS 握手（Linux/macOS）
   openssl s_client -connect im-api.company.com:443 -tls1_2
   ```

### 步骤 2：客户端日志采集
- **Windows**：`%LOCALAPPDATA%\CompanyIM\logs\latest.log`  
- **macOS**：`~/Library/Logs/CompanyIM/latest.log`  
- **关键检索关键词**：`LoginFailed`、`AuthError`、`SSLHandshakeException`、`401`、`403`、`502`

### 步骤 3：检查本地环境依赖
| 组件 | Windows 要求 | macOS 要求 |
|------|----------------|-------------|
| TLS 版本 | 必须启用 TLS 1.2（注册表路径：`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.2\Client` → `Enabled = 1`） | 系统默认启用（macOS 10.15+） |
| 运行时 | .NET Desktop Runtime 6.0.27+（[下载地址](https://dotnet.microsoft.com/download/dotnet/6.0)） | Apple Silicon：需 Rosetta 2 兼容模式（如适用） |
| 证书信任 | 根证书需包含 `Company Internal CA`（检查 `certmgr.msc` → “受信任的根证书颁发机构”） | Keychain 中导入 `Company-Root-CA.crt` 并设为「始终信任」 |

### 步骤 4：服务端侧验证（需 IT 运维权限）
- 登录 IAM 管理后台 → 检查用户状态是否为 `Active` 且 `MFA Enabled = true`  
- 查询用户最近登录审计日志（路径：`Admin Console > Security > Audit Logs > Filter: Event=LoginFailure`）  
- 验证 API 网关健康状态：访问 `https://status.company.com/im-gateway`（返回 `{"status":"healthy","uptime_sec":12489}`）

---

## 三、高频错误码速查表

| 错误码 | 含义 | 解决动作 |
|--------|------|-----------|
| `401 Unauthorized` | 凭据无效或 Token 过期 | 清除客户端缓存（设置 → 高级 → 「重置登录状态」） |
| `403 Forbidden` | 权限不足（如 OU 移动未同步） | 联系 HRIS 确认员工组织架构变更已推送至 IAM |
| `502 Bad Gateway` | IM 网关与后端 Auth 服务通信失败 | 检查 `im-gateway` Pod 日志（K8s 命令：`kubectl logs -n im deploy/im-gateway -c auth-proxy`） |
| `SSL_ERROR_BAD_CERT_DOMAIN` | 客户端证书域名不匹配 | 更新客户端至最新版（v3.9.1+ 已修复 `*.im-api.company.com` 通配符证书兼容问题） |

---

## 四、附：紧急恢复操作（仅限管理员）

若批量用户出现登录失败，可临时启用降级模式（需重启客户端）：
1. 在客户端安装目录创建空文件：`disable-mfa-check.flag`  
2. 启动参数追加：`--force-tls12 --skip-certificate-verify`（**生产环境禁用，仅限故障定位**）  
3. 故障解除后立即删除 flag 文件并重装合规证书。

> 🔒 安全提示：跳过证书校验会削弱传输层安全，请在 2 小时内恢复标准配置。
