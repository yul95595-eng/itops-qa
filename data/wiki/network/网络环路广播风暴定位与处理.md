# 网络环路广播风暴定位与处理

## 概述  
当二层网络中存在物理或逻辑环路（如交换机端口误接、STP未启用/失效、堆叠/虚拟化配置异常等），广播帧将被不断复制转发，导致**广播风暴**。其典型表现为：网络延迟激增、设备CPU持续100%、端口流量突增至线速、终端间通信中断、ARP表项频繁刷新甚至清空。本指南适用于公司核心/接入层以太网交换网络（含H3C、华为、Cisco主流厂商设备）的环路快速定位与处置。

---

## 常见诱因与风险等级

| 风险等级 | 诱因类型 | 典型场景 | 检测难度 |
|----------|-----------|------------|------------|
| ⚠️ 高危 | 物理环路 | 同一交换机两接口直连；跨交换机双链路未启STP；员工私接Hub/傻瓜交换机形成闭环 | 低（可通过端口流量/错误计数快速识别） |
| ⚠️ 高危 | STP失效 | STP被全局关闭；根桥选举异常（如优先级配置冲突）；BPDU报文被ACL过滤或VLAN隔离 | 中（需检查STP状态及拓扑数据库） |
| ⚠️ 中高 | 虚拟化环路 | VRRP+MSTP配置不一致；堆叠分裂后双主运行；SDN控制器下发流表错误导致逻辑环路 | 高（依赖厂商特定诊断命令） |
| ⚠️ 中危 | 配置错误 | Trunk端口允许VLAN范围不匹配导致BPDU无法传递；PortFast在上行口误启用 | 中 |

> 💡 **关键提示**：广播风暴下，设备可能无法响应SSH/Telnet，应优先通过**Console口本地登录**进行排查。

## 快速定位步骤（黄金10分钟）

### 步骤1：确认风暴现象（1分钟）
- 使用`ping -t 192.168.1.1`（网关IP）观察丢包率是否 >95% 且延迟 >500ms  
- 查看核心交换机Syslog：`display logbuffer | include "broadcast|storm|cpu 100"`（华为/H3C）或 `show logging | grep -i "broadcast|storm"`（Cisco）

### 步骤2：定位异常端口（3分钟）
```bash
# 华为/H3C 示例（逐台登录核心/汇聚层设备执行）
display interface brief | include UP     # 找出流量异常飙升的UP端口（InUti/OutUti >80%）
display transceiver diagnosis interface GigabitEthernet1/0/1  # 检查光模块是否因风暴过热告警
```

### 步骤3：验证STP状态（3分钟）
```bash
# 检查STP是否启用及根桥角色
display stp brief
display stp root
display stp topology-change  # 查看TC（拓扑变更）统计，>10次/分钟即异常
```
✅ **正常特征**：仅1台设备Role=ROOT，其余为DESI/ALTE；TC计数稳定（≤1次/5分钟）  
❌ **异常特征**：多台ROOT；所有端口Role=DESI；TC计数暴涨；`display stp abnormal-port` 显示非零输出

### 步骤4：物理环路隔离（2分钟）
- 对疑似环路区域（如同一机柜、同一楼层配线架），**逐个拔除冗余链路光纤/网线**，每拔一根观察：
  - `display cpu-usage` 是否从100%降至<40%
  - `ping` 网关丢包率是否恢复至0%
- ✅ **定位成功标志**：某根线缆拔除后，CPU与流量指标立即恢复正常

### 步骤5：日志归档与根因分析（1分钟）
```bash
# 保存关键诊断信息（用于事后复盘）
display stp region-configuration > flash:/stp_config.log
display interface brief > flash:/if_brief.log
display transceiver diagnosis all > flash:/optical_diag.log
```

## 标准处置流程

1. **紧急抑制**  
   - 在风暴源附近交换机执行：  
     `system-view` → `interface GigabitEthernet1/0/1` → `broadcast-suppression 1000`（限制广播带宽为1Mbps，华为/H3C）  
     *注：此为临时措施，不可替代环路清除*

2. **永久修复**  
   - ✅ 启用并校验STP：  
     ```bash
     stp enable  
     stp mode mstp  
     stp priority 4096  # 确保核心设备为根桥（数值越小优先级越高）
     ```
   - ✅ 关闭非必要端口：对未使用的Access端口执行 `shutdown`  
   - ✅ 启用环路防护：  
     `stp loop-protection`（上游端口） + `stp root-protection`（根桥下行端口）

3. **验证闭环**  
   - 执行 `display stp topology` 确认生成树收敛（MaxAge=20s, Hello=2s, ForwardDelay=15s）  
   - 使用网络抓包工具（如Wireshark）在任意PC上捕获，过滤 `eth.dst == ff:ff:ff:ff:ff:ff`，确认广播帧数量回归基线（<50帧/秒）

## 常见错误码与对策

| 错误现象 | 设备日志关键字 | 可能原因 | 解决方案 |
|-----------|------------------|-------------|--------------|
| STP端口持续阻塞 | `%SPANNING-TREE-2-RECV_PVST_ON_NON_TRUNK` | PVST+报文在非Trunk口收到 | 检查VLAN配置，确保Trunk口允许对应VLAN |
| BPDU发送失败 | `BPDU sent failed on port X/X` | 端口被ACL拒绝协议报文 | `undo traffic-filter inbound` 清除影响BPDU的ACL |
| TC通知泛滥 | `Topology Change detected on VLAN X` | 网络中存在震荡链路 | 使用`display transceiver fault`检查光模块故障，更换劣质跳线 |
| CPU占用100%但无STP异常 | `CPU utilization exceeded 90% for 5 minutes` | 广播风暴触发MAC地址表溢出学习 | 启用`mac-address flapping detection`并绑定端口MAC |

## 预防性加固建议

- **配置基线强制**：所有新入网交换机必须启用 `stp enable` + `stp bpdu-protection`（边缘端口BPDU保护）  
- **物理层管控**：配线架标签标准化，禁止使用无管理能力的Hub/交换机；部署DCIM系统监控端口连接关系  
- **监控告警集成**：在Zabbix/Prometheus中配置阈值告警：  
  - `ifInBroadcastPkts.1 > 1000000`（单端口每秒广播包超100万）  
  - `hrProcessorLoad.1 = 100`（CPU持续100%达30秒）  
- **变更管理卡点**：任何涉及Trunk/VLAN/STP的配置变更，须经`display stp check`预检并通过变更窗口审批  

> 📌 **附：STP快速检查清单**  
> - [ ] 所有设备 `display stp global` 显示 `STP Status: ENABLED`  
> - [ ] 核心设备 `display stp root` 显示 `Root Bridge ID: 4096.xxx-xxx-xxx`（优先级4096）  
> - [ ] 接入层设备 `display stp brief` 中非上行端口 Role=DESIGNATED，上行端口 Role=ROOT  
> - [ ] `display stp abnormal-port` 输出为空
