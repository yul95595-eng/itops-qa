# 网关地址冲突定位与解决

## 概述  
网关地址冲突是指多个网络设备（如企业分支路由器、SSL VPN 客户端虚拟网卡、本地默认网关或容器宿主机）被配置为使用相同 IP 地址作为默认网关，导致路由表混乱、流量转发异常、内网访问失败或 VPN 连接后无法访问本地资源等问题。该问题在混合办公、多链路接入及容器化部署场景中尤为常见。

---

## 常见现象

- SSL/IPSsec VPN 连接成功，但无法访问公司内网服务（如 OA、GitLab）  
- 本地局域网设备（如打印机、NAS）突然不可达  
- `ping` 内网地址通，`tracert` / `mtr` 显示路径异常跳转  
- `route print`（Windows）或 `ip route show`（Linux/macOS）中出现重复/重叠的 `0.0.0.0/0` 或 `default` 条目  
- 日志中出现 `RTNETLINK answers: File exists`（Linux）、`The parameter is incorrect.`（Windows 路由添加失败）

---

## 冲突定位步骤

### 1. 查看当前路由表（关键诊断入口）

| 系统平台 | 命令 | 说明 |
|----------|------|------|
| Windows | `route print -4 \| findstr "0.0.0.0"` 或 `Get-NetRoute -DestinationPrefix "0.0.0.0/0"` | 过滤 IPv4 默认路由，关注 `Network Destination` 和 `Gateway` 列 |
| Linux | `ip route show default` 或 `ip route | grep '^default\|via'` | 检查是否存在多条 `default via x.x.x.x` |
| macOS | `netstat -rn \| grep 'default'` 或 `route -n get default` | 注意 `interface` 是否异常（如 `utun3` 为 VPN 接口） |

> ✅ **判断标准**：若存在两条及以上 `default` 路由，且下一跳网关 IP 相同（或属于同一子网），即存在潜在冲突。

### 2. 识别网关来源设备

执行以下操作确认各网关归属：

- 检查物理/虚拟网卡配置：
  ```bash
  # Linux 示例：查看所有接口网关（通过 DHCP 获取的网关通常在 dhcpd.leases 或 systemd-networkd 中）
  ip addr show \| grep -A2 "inet "
  cat /var/lib/dhcp/dhclient.*.leases 2>/dev/null \| grep "option routers"
  ```
- 检查 VPN 客户端配置：
  - FortiClient / Palo Alto GlobalProtect / Cisco AnyConnect：查看「连接设置 → 高级 → 推送路由」是否启用 `Full Tunnel` 或自定义 `Split Tunneling` 子网；
  - OpenConnect / StrongSwan：检查 `--route` 参数或 `ipsec.conf` 中 `leftsubnet`/`rightsubnet` 是否覆盖本地网段。
- 检查容器/虚拟化环境：
  - Docker：`docker network inspect bridge` 查看 `Gateway` 字段；
  - Kubernetes：`kubectl get nodes -o wide` + `ip route show table local`，注意 `cni0`、`flannel.1` 等接口网关。

### 3. 分析路由优先级（Metric / Preference）

| 平台 | 优先级依据 | 冲突时表现 |
|------|-------------|-------------|
| Windows | `Metric` 值越小优先级越高；相同 Metric 时按接口绑定顺序 | 若两个 default 路由 Metric 均为 25 | 系统行为不确定，易丢包 |
| Linux | `metric`（`ip route add ... metric N`），默认 `0` 最高；Kernel 使用 `fib_rules` 控制策略路由 | 多 default 导致 `ip rule show` 出现冗余规则 |
| macOS | `Priority`（`route -n get default` 输出），值越小越优先 | 同 Priority 下 Kernel 随机选路 |

> ⚠️ 注意：某些客户端（如旧版 Cisco AnyConnect）会强制将 `metric=1` 写入 default 路由，覆盖物理网卡原有低 metric 路由，造成“连上 VPN 就断本地网”。

## 标准解决流程（有序步骤）

1. **临时规避（验证用）**  
   - Windows：`route delete 0.0.0.0 mask 0.0.0.0 <冲突网关IP>`  
   - Linux：`sudo ip route del default via <冲突网关IP>`  
   - macOS：`sudo route delete default <冲突网关IP>`  
   > ✅ 成功后测试本地与内网连通性，确认是否为该路由导致。

2. **永久修复方案选择**  
   - ✅ **首选：调整 VPN 客户端路由策略（Split Tunneling）**  
     - 在 VPN 配置中仅推送业务必需子网（如 `10.100.0.0/16`, `172.16.5.0/24`），禁用 `Full Tunnel`；  
     - 若必须 Full Tunnel，启用「允许本地网络访问（Allow local LAN access）」选项（适用于 FortiClient / Pulse Secure）。

   - ✅ **次选：修改本地网关 Metric（Windows/Linux）**  
     - Windows：`netsh interface ipv4 set interface "以太网" metric=10`（设为高于 VPN 接口的 metric，如 VPN 为 5，则设为 10）；  
     - Linux：编辑 `/etc/systemd/network/*.network`，添加 `RouteMetric=200`。

   - ✅ **容器/云环境适配**  
     - Docker：启动容器时加 `--network host` 或自定义网络 `--gateway 172.20.0.1` 避免与宿主机 `172.17.0.1` 冲突；  
     - Kubernetes：检查 CNI 插件（Calico/Flannel）配置中 `podSubnet` 与节点物理网段是否重叠。

3. **验证与固化**  
   - 执行 `ip route show table all 2>/dev/null \| grep default`（Linux）或 `route print`（Win）确认唯一 default 路由；  
   - 使用 `curl -v http://internal-api.company.local` + `tcpdump -i any port 80` 抓包确认流量经预期网关转发；  
   - 将修复命令/配置写入启动脚本（如 Linux `systemd service` / Windows `Task Scheduler` 开机任务）。

## 附录：典型错误码与含义

| 错误信息 | 平台 | 原因 | 解决方向 |
|----------|------|------|-----------|
| `SIOCADDRT: Network is unreachable` | Linux | 新增路由的网关本身不可达（如网关 IP 不在任一本地子网） | 先 `ping` 网关，检查接口 UP 状态及子网掩码 |
| `The object already exists.` | Windows | 试图添加已存在的路由条目 | `route print` 后先 `route delete` 再 `add` |
| `RTNETLINK answers: No such process` | Linux | 删除不存在的路由 | 使用 `ip route flush cache` 清理 FIB 缓存后重试 |
| `VPN tunnel established but no traffic` | AnyConnect | `ipconfig` 显示 `Default Gateway: 0.0.0.0`（因未推送路由） | 检查 ASA/FMC 策略中 `split-tunnel-policy tunnelspecified` 及 `split-tunnel-network-list` ACL |
