# 公司邮箱收发信网络依赖排查指南

> 本文档适用于公司 IT 运维人员及终端用户自助排查邮箱（基于 Microsoft Exchange Online / Outlook Web App 或 Outlook 客户端）无法正常收发邮件的网络连通性问题。重点聚焦**网络层与应用层依赖路径**，不涉及邮箱账户配置、权限或 Exchange 后台策略问题。

---

## 一、核心网络依赖路径概览

公司邮箱（Exchange Online）依赖以下关键网络服务节点，任一环节中断均可能导致收发失败：

| 依赖类型 | 协议/端口 | 目标域名（示例） | 用途说明 | 是否需经公司 VPN |
|----------|------------|------------------|-----------|-------------------|
| DNS 解析 | UDP/TCP 53 | `8.8.8.8` 或公司内网 DNS | 解析 `outlook.office365.com` 等域名 | 否（但建议优先使用公司 DNS） |
| TLS 握手与 HTTPS 访问 | TCP 443 | `outlook.office365.com`<br>`autodiscover.outlook.com`<br>`login.microsoftonline.com` | Web 邮箱访问、自动发现、身份认证 | **是**（若策略要求所有办公流量强制过 VPN） |
| SMTP/IMAP/POP3（客户端） | TCP 587（SMTP TLS）<br>TCP 993（IMAP SSL）<br>TCP 995（POP3 SSL） | `smtp.office365.com`<br>`outlook.office365.com` | Outlook 客户端邮件同步 | **视策略而定**：远程办公通常需 VPN；直连公网需放行对应端口 |
| MTA 通信（内部中继场景） | TCP 25/587 | `mail-relay.corp.local`（如部署了边缘传输） | 内部系统发信中继（非标准云直连模式） | 是（仅限内网或 VPN 接入） |

> ✅ **关键提示**：  
> - Exchange Online **不支持明文协议（如 SMTP 25 不加密、IMAP 143）**，强制要求 TLS 加密；  
> - `autodiscover.` 域名解析失败是 Outlook 客户端配置失败的最常见原因；  
> - 若启用「Split Tunneling」（分流隧道），需确保 Office 365 相关域名**明确排除在 VPN 隧道外**（推荐微软官方 [Office 365 IP 和 URL 范围](https://learn.microsoft.com/zh-cn/microsoftteams/office-365-url-web-proxy-configuration)）。

## 二、分步排查流程（终端用户 & IT 支持通用）

### 步骤 1：确认基础网络连通性
1. 打开命令提示符（Windows）或终端（macOS/Linux）；
2. 执行：
   ```bash
   ping -c 4 outlook.office365.com
   ```
   - ✅ 预期结果：`Reply from ...`（非 `Request timed out`）；  
   - ❌ 若失败：检查本地网络、防火墙拦截、DNS 解析是否异常（见步骤 2）。

### 步骤 2：验证 DNS 解析
```bash
nslookup autodiscover.outlook.com
nslookup login.microsoftonline.com
```
- ✅ 应返回 `canonical name = autodiscover.outlook.com` 及有效 A/AAAA 记录；  
- ❌ 若返回 `Non-existent domain` 或超时：  
  - 切换 DNS（如临时设为 `8.8.8.8` 或 `114.114.114.114`）重试；  
  - 检查公司 DNS 是否屏蔽/劫持了 Microsoft 域名（常见于老旧安全网关）。

### 步骤 3：测试 HTTPS/TLS 连通性（关键！）
```bash
# Windows（PowerShell）
Test-NetConnection outlook.office365.com -Port 443

# macOS/Linux
nc -zv outlook.office365.com 443
openssl s_client -connect outlook.office365.com:443 -servername outlook.office365.com
```
- ✅ 成功标志：`TcpTestSucceeded : True` 或 `Connection succeeded`；  
- ❌ 失败常见原因：
  - 公司防火墙/代理拦截 TLS 握手（尤其自签名证书中间人设备）；  
  - VPN 未正确加载 Office 365 分流规则，导致 HTTPS 流量被错误转发至内网网关；  
  - 本地 hosts 文件硬编码错误 IP（检查 `C:\Windows\System32\drivers\etc\hosts` 或 `/etc/hosts`）。

### 步骤 4：验证自动发现服务（Outlook 客户端专属）
1. 在 Outlook 中按住 `Ctrl` 键右击系统托盘 Outlook 图标 → 选择 **“测试电子邮件自动配置…”**；  
2. 输入邮箱地址与密码，勾选 **“使用自动发现”**，点击 **“测试”**；  
3. 查看日志中的 `Autodiscover` 行：  
   - ✅ `HTTP Response Code = 200` + `Autodiscover response XML received`；  
   - ❌ `HTTP Response Code = 403` → 代理/防火墙拒绝；  
   - ❌ `HTTP Response Code = 404` → DNS 解析到错误服务器（如旧 Exchange 服务器）；  
   - ❌ `The remote name could not be resolved` → DNS 失败（回溯步骤 2）。

### 步骤 5：检查代理与浏览器设置（Web 邮箱场景）
- 确保浏览器未启用系统代理或手动代理（尤其企业 IE/Edge 组策略代理）；  
- 在 Chrome/Firefox 中访问 `chrome://settings/system` → 关闭 **“使用系统代理设置”**；  
- 若公司强制使用代理，请确认代理服务器已放行 `*.office365.com` 和 `*.microsoftonline.com` 的 CONNECT 方法（端口 443）。

## 三、常见错误码速查表

| 错误现象 | 错误码 / 日志关键词 | 可能原因 | 排查方向 |
|----------|----------------------|-----------|------------|
| Outlook 提示“无法连接到 Microsoft Exchange” | `0x8004010F` | 自动发现失败 | 步骤 2、4 |
| Web 邮箱白屏/加载卡死 | `ERR_CONNECTION_TIMED_OUT` | 443 端口阻断 | 步骤 3、VPN 分流配置 |
| 发信失败提示“5.7.57 SMTP; Client was not authenticated” | SMTP 535 | 凭据错误或 MFA 未通过 | 检查是否启用现代身份验证（Modern Auth） |
| 收件延迟 >5 分钟 | `421 4.7.0 Temporary server error` | TLS 握手不稳定或源 IP 被限频 | 抓包分析 TLS handshake（Wireshark 过滤 `tls.handshake`） |
| 移动端（Outlook App）反复要求登录 | `AADSTS50058` | 会话 Cookie 丢失或代理篡改 | 检查移动设备是否安装企业 CA 证书、代理策略 |

## 四、附录：快速验证脚本（Windows PowerShell）

```powershell
# 一键执行基础连通性检测（以管理员身份运行）
$targets = @("outlook.office365.com", "autodiscover.outlook.com", "login.microsoftonline.com")
Write-Host "🔍 开始检测 Office 365 核心域名..." -ForegroundColor Green
foreach ($t in $targets) {
    Write-Host "`n=== $t ===" -ForegroundColor Cyan
    if (Resolve-DnsName $t -ErrorAction SilentlyContinue) {
        Write-Host "✅ DNS 解析成功" -ForegroundColor Green
        if (Test-NetConnection $t -Port 443 -ErrorAction SilentlyContinue | 
            Select-Object -ExpandProperty TcpTestSucceeded) {
            Write-Host "✅ HTTPS 443 连通正常" -ForegroundColor Green
        } else { Write-Host "❌ HTTPS 443 连接失败" -ForegroundColor Red }
    } else { Write-Host "❌ DNS 解析失败" -ForegroundColor Red }
}
```

> ⚠️ 注意：该脚本需 PowerShell 5.1+，且目标主机需允许 ICMP 与 TCP 探测。
