# 链路冗余与主备切换演练方案

> **文档版本**：v2.3  
> **最后更新**：2024-06-15  
> **适用对象**：网络运维工程师、SRE、安全合规负责人  
> **所属知识域**：网络与VPN  

---

## 一、目标与范围

### 1.1 演练目标  
- 验证公司广域网（WAN）核心链路双上行（MPLS + Internet VPN）的自动/手动主备切换能力；  
- 确保关键业务系统（如ERP、OA、视频会议）在主链路中断后 <30 秒内完成故障转移，业务影响时间 ≤ 90 秒；  
- 检验 BGP 路由收敛、IPsec SA 重协商、SD-WAN 控制器策略同步等关键环节的健壮性；  
- 更新《网络高可用SOP》及《应急响应手册》中对应章节。

### 1.2 演练范围  
| 类别         | 覆盖内容                                                                 |
|--------------|--------------------------------------------------------------------------|
| **网络层级** | 核心出口路由器（AR3260）、SD-WAN 边缘节点（vEdge-2000）、防火墙（USG6650） |
| **链路类型** | 主链路：MPLS（AS65001，BGP peering）<br>备链路：IPsec over Internet（IKEv2，AES-256-GCM） |
| **业务系统** | ERP（10.20.1.0/24）、统一身份认证平台（10.20.5.0/24）、云视频会议（SaaS，FQDN白名单） |

> ⚠️ **不覆盖范围**：数据中心内部二层冗余（如堆叠交换机）、无线网络冗余、非VPN接入终端（如4G CPE）。

## 二、前置检查清单（演练前48小时）

请按顺序执行并记录结果：

1. ✅ 确认所有设备 NTP 同步状态（`display ntp status`），时钟偏差 ≤ 500ms；  
2. ✅ 验证主备链路当前路由表一致性（`display ip routing-table protocol bgp` / `display ipsec sa`）；  
3. ✅ 检查 SD-WAN 控制器中 `overlay-tunnel-status` 为 `UP`，且 `control-connection` 无 `DEGRADED` 状态；  
4. ✅ 备份当前配置（含 startup-config 和 running-config），存档至 GitLab `/network/config-backup/2024Q2/failover-drill/`；  
5. ✅ 通知关联方（应用运维、安全团队、一线客服）演练窗口期（T+0 14:00–15:30）及预期影响；  
6. ✅ 在监控平台（Zabbix + Grafana）启用「链路切换专项看板」，预置告警抑制规则（避免误报）。

## 三、主备切换演练步骤（标准流程）

### 3.1 手动触发主备切换（推荐首次演练使用）

| 步骤 | 操作命令/动作 | 预期响应 | 验证方式 |
|------|----------------|-----------|------------|
| 1 | 在主出口路由器执行：<br>`[AR3260] interface GigabitEthernet0/0/1`<br>`[AR3260-GigabitEthernet0/0/1] shutdown` | 接口状态变为 `DOWN`，BGP session 断开（`display bgp peer` 显示 `Idle` 或 `Active`） | `display interface GigabitEthernet0/0/1` 输出 `Administratively DOWN` |
| 2 | 观察 10 秒内 SD-WAN 控制器日志：<br>`show control connections \| include "state.*up"` | 备链路隧道状态由 `INIT` → `ESTABLISHED`，控制连接重建成功 | 控制器 Web UI 中 `Tunnel Status` 列显示绿色 `UP` |
| 3 | 在核心防火墙执行：<br>`display ipsec sa` | 新建 SA 使用 `tunnel 10.100.2.0/30`（备链路子网），SPI 不为 `0x0` | SA 生命周期应为 `28800s`（8h），加密算法为 `AES-GCM-256` |
| 4 | 从客户端（10.20.1.100）执行：<br>`ping -c 5 10.20.5.10`<br>`traceroute 10.20.5.10` | 丢包 ≤1，路径跳转至 `10.100.2.1`（备链路下一跳） | `traceroute` 第3跳应为 `10.100.2.1`，而非原 `10.100.1.1` |

### 3.2 自动切换验证（BGP 故障注入）

> 仅在手动切换成功后执行。模拟主链路物理中断（非管理关闭）。

- **操作**：拔除 AR3260 的 `GigabitEthernet0/0/1` 光模块（保持接口 `no shutdown`）；
- **关键指标**：
  - BGP Hold Timer 超时时间：默认 180s → 实际收敛时间应 ≤ 45s（因启用 `fast-external-fallover`）；
  - IPsec SA 重协商延迟：≤ 8s（受 IKEv2 rekey timer 影响）；
- **失败判定**：若 `display bgp routing-table 10.20.5.0` 仍显示 `inactive` 或 `best` 路由未切换，则触发回滚流程。

## 四、常见问题与处置指南

| 错误现象 | 可能原因 | 应急处置 |
|----------|-----------|------------|
| **BGP 路由未切换，`display bgp routing-table` 仍显示主链路路由但状态为 `Invalid`** | BGP `next-hop-self` 未在 RR 上配置，或 IBGP 下一跳不可达 | 手动清除 BGP 表：<br>`reset bgp all` → 等待 30s → `display bgp routing-table` 确认新路径 |
| **IPsec SA 建立失败，日志提示 `NO_PROPOSAL_CHOSEN`** | 主备两端 IKE 提议不匹配（如一端用 AES-128-CBC，另一端用 AES-256-GCM） | 检查 `display ike proposal`，统一为 `proposal IKEv2-PROD`（含 AES-256-GCM, SHA2-384, DH-group19） |
| **SD-WAN 控制器显示隧道 `UP`，但业务流量未走备链路** | 策略路由（PBR）未匹配新隧道接口，或 `service-routing` 规则未启用 | `display policy-based-route rule` → 检查 `apply output-interface` 是否指向 `tunnel 10.100.2.0`；必要时 `undo service-routing enable` 后重配 |
