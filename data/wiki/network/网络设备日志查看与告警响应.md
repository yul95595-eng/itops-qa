# 网络设备日志查看与告警响应

## 1. 概述  
本指南适用于公司网络运维人员，用于规范核心网络设备（含路由器、交换机、防火墙及VPN网关）的日志采集、实时查看、关键事件识别及标准化告警响应流程。目标是提升故障定位效率，降低MTTR（平均修复时间），并满足等保2.0中关于日志留存≥180天及安全审计的要求。

---

## 2. 日志访问方式汇总  

| 设备类型       | 接入协议 | 默认端口 | 认证方式         | 日志存储位置（典型）         |
|----------------|----------|----------|------------------|------------------------------|
| 华为 USG/NE 系列 | SSH/Telnet | 22/23    | 账号密码 / Radius | `display logbuffer` / `/var/log/`（Syslog服务器） |
| Cisco IOS/XE     | SSH      | 22       | AAA / Local Auth | `show logging` / Syslog Server（UDP 514）        |
| H3C SecPath 防火墙 | SSH      | 22       | 本地账号或LDAP   | `display logbuffer` / `display syslog`           |
| FortiGate（VPN网关）| HTTPS/SSH | 443/22   | Admin账号        | GUI: Log & Report → Forward Traffic；CLI: `diagnose debug application fnbamd -1` |

> ✅ **提示**：所有设备必须启用UTC时区并同步NTP（推荐指向公司内部NTP服务器 `ntp.company.local`），避免日志时间偏差导致关联分析失败。

## 3. 关键日志识别与告警等级定义  

### 3.1 高危事件（需5分钟内响应）  
- `SYSLOG-3-CONFIG_I`: 配置被非授权修改（如 `user admin changed interface GigabitEthernet0/1`）  
- `SEC-6-IPSEC_TUNNEL_DOWN`: IPsec SA异常中断（连续3次重协商失败）  
- `FW-4-DROP_PKT`: 防火墙策略匹配丢包率突增 >15%（对比前1小时基线）  
- `BGP-5-ADJCHANGE`: BGP邻居状态从`Established`变为`Idle/Active`（非计划维护场景）

### 3.2 中风险事件（30分钟内响应）  
- `SNMP-5-NOTIFICATION`: SNMP trap接收异常（连续5分钟无心跳trap）  
- `VPN-4-AUTH_FAIL`: SSL VPN用户认证失败 ≥10次/5分钟（疑似暴力破解）  
- `INTERFACE-3-IF_DOWN`: 核心链路接口物理Down（非计划性）

## 4. 标准化告警响应流程（SOP）

### 4.1 初步确认（0–5分钟）
1. 登录集中日志平台（ELK Stack / Splunk），筛选告警设备IP、时间范围及关键词（如 `ERROR`, `DOWN`, `DENY`）；  
2. 执行 `ping` + `traceroute` 验证设备可达性与路径连通性；  
3. 检查设备CPU/内存使用率（CLI命令示例：`show processes cpu sorted | exclude 0.00`）；  
4. 若为VPN网关，检查证书有效期：`show vpn certificate local`（FortiGate）或 `display pki certificate access-control`（华为）；  
5. 记录原始日志片段（含时间戳、设备名、序列号）至工单系统。

### 4.2 根因分析（5–30分钟）
- **BGP中断**：执行 `show bgp ipv4 unicast summary` → `show bgp ipv4 unicast neighbors X.X.X.X advertised-routes` → 检查TCP连接（`show tcp brief`）；  
- **IPsec隧道失效**：比对两端SA参数（加密算法、DH组、lifetime）是否一致，检查NAT-T是否启用；  
- **接口Down**：核查光模块收发光功率（`show interfaces transceiver detail`），排除物理层故障。

### 4.3 处置与闭环
- 短期恢复：启用备用路径（如切换BGP下一跳）、重启服务进程（`reset ipsec sa`）、临时放宽ACL规则；  
- 长期修复：提交变更请求（RFC），更新配置模板，同步至GitLab配置库；  
- 工单闭环前，须验证日志中对应错误条目停止产生 ≥15分钟，并截图归档。

## 5. 常见错误码速查表  

| 错误码（Syslog Tag） | 含义                          | 推荐操作                                  |
|----------------------|-------------------------------|-------------------------------------------|
| `%ASA-4-106023`      | 防火墙ACL显式拒绝流量           | 检查访问控制策略顺序，确认源/目的IP、端口匹配逻辑 |
| `%SW_MATM-4-MACFLAP_NOTIF` | MAC地址在不同端口频繁漂移（环路嫌疑） | 执行 `show spanning-tree vlan X`，关闭可疑端口 |
| `%CRYPTO-4-IKMP_NO_SA` | IKE Phase1协商失败（预共享密钥不匹配） | 核对两端PSK、身份标识（ID Type）、本地/远端地址 |
| `%LINEPROTO-5-UPDOWN` | 接口线路协议状态变化            | 结合`%LINK-3-UPDOWN`判断是物理层还是协议层问题 |

> ⚠️ 注意：`%SYS-2-CONFIG_I` 类日志若出现在非维护窗口，必须立即启动安全事件响应（参考《公司网络安全事件应急预案》第4.2节）。
