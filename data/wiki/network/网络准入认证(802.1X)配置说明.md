# 网络准入认证（802.1X）配置说明

> **适用范围**：公司内网有线/无线接入设备（交换机、无线控制器）、终端设备（Windows/macOS/Linux）、RADIUS服务器（如FreeRADIUS、Microsoft NPS）

---

## 一、802.1X 认证原理简述

802.1X 是基于端口的网络访问控制协议，采用 **EAP（Extensible Authentication Protocol）** 框架，通过三元组实现认证：
- **Supplicant（客户端）**：终端设备（如员工笔记本）
- **Authenticator（认证者）**：接入设备（如接入交换机或AP）
- **Authentication Server（认证服务器）**：RADIUS服务器（如FreeRADIUS）

认证流程为：  
`Supplicant → Authenticator → RADIUS Server`（EAP中继或EAP终结模式）

## 二、核心组件配置要求

### 2.1 接入设备（以华为S5735-S为例）

#### ✅ 必配项
```bash
# 启用全局802.1X
[Switch] dot1x enable

# 在接入端口启用802.1X（例：GigabitEthernet0/0/1）
[Switch] interface gigabitethernet 0/0/1
[Switch-GigabitEthernet0/0/1] port link-type access
[Switch-GigabitEthernet0/0/1] dot1x enable
[Switch-GigabitEthernet0/0/1] dot1x port-method mac   # 可选：按MAC地址认证（适用于IP电话等哑终端）
[Switch-GigabitEthernet0/0/1] quit

# 配置RADIUS服务器模板（假设RADIUS IP为10.10.200.10，共享密钥为NAC@2024）
[Switch] radius-server template nac-radius
[Switch-radius-nac-radius] radius-server shared-key cipher NAC@2024
[Switch-radius-nac-radius] radius-server authentication 10.10.200.10 1812 weight 80
[Switch-radius-nac-radius] radius-server accounting 10.10.200.10 1813 weight 80
[Switch-radius-nac-radius] quit

# 绑定RADIUS模板至802.1X认证
[Switch] dot1x authentication-method radius
[Switch] dot1x radius-server nac-radius
```

#### ⚠️ 注意事项
- 端口必须为 `access` 模式（不支持trunk口直连802.1X终端）
- 若启用 `dot1x port-control auto`（默认），端口初始为未授权状态，仅允许EAPOL帧通过
- 建议配置 `dot1x timeout tx-period 30`（重传间隔）和 `max-user 10`（单端口最大用户数）

### 2.2 Windows 客户端配置（Windows 10/11）

| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| 网络身份验证方法 | **Microsoft: Protected EAP (PEAP)** | 兼容性最佳，支持证书+用户名密码 |
| 内部身份验证方法 | **Secured password (EAP-MSCHAP v2)** | 不推荐使用明文EAP-MD5 |
| 服务器证书验证 | ✅ 启用，指定受信任根CA | 防止中间人攻击；CA证书需预置到“受信任的根证书颁发机构” |
| 用户凭据 | 使用域账号（如 `CORP\username`）或本地账户 | 需与RADIUS后端用户库一致 |

> 🔍 **排错提示**：若连接失败且事件查看器报错 `Event ID 6273`（EAP 失败），常见原因包括：  
> - 服务器证书不受信（证书链不完整或域名不匹配）  
> - 用户密码过期或被锁定  
> - RADIUS返回 `Access-Reject`（检查FreeRADIUS日志 `/var/log/freeradius/radius.log`）

### 2.3 FreeRADIUS 服务端关键配置（v3.2+）

#### `/etc/freeradius/3.0/sites-enabled/default`
```apache
authorize {
    ...
    # 启用mschap模块处理Windows认证
    mschap
    # 允许从LDAP/AD同步用户（需配置mods-available/ldap）
    ldap
    ...
}

authenticate {
    Auth-Type MS-CHAP {
        mschap
    }
}
```

#### `/etc/freeradius/3.0/mods-config/files/authorize`
```
# 示例：允许特定OU下的AD用户接入
DEFAULT Ldap-Group == "CN=Network-Users,OU=Groups,DC=corp,DC=local", Auth-Type := mschap
```

#### ✅ 必须验证的运行状态
```bash
# 检查服务状态
sudo systemctl status freeradius

# 测试本地认证（模拟客户端）
radtest testuser 'P@ssw0rd' 127.0.0.1 0 testing123

# 查看实时调试日志（生产环境慎用）
sudo freeradius -X
```

## 三、典型故障排查流程（有序步骤）

1. **确认物理与基础连通性**  
   - 检查客户端网线/无线信号是否正常  
   - `ping` 接入交换机管理IP及RADIUS服务器IP（确保三层可达）

2. **抓包验证EAPOL交互**  
   - 在客户端侧用Wireshark过滤 `eapol || radius`  
   - 正常流程应出现：`EAP-Request/Identity → EAP-Response/Identity → EAP-Request/PEAP → ... → EAP-Success`

3. **检查交换机端口状态**  
   ```bash
   display dot1x interface gigabitethernet 0/0/1
   # 关注字段：Current State（Authorized/Unauthorized）、User Num、Last Failure Reason
   ```

4. **核查RADIUS服务器日志**  
   - 查找 `Access-Reject` 原因码（如 `Reason-Code = 201` 表示用户不存在）  
   - 常见错误码对照表：

   | 错误码 | 含义 | 解决建议 |
   |--------|------|-----------|
   | `201` | User not found | 检查LDAP绑定DN、搜索Base DN、用户是否在目标OU |
   | `202` | Invalid password | 密码策略不一致（如AD密码过期、大小写敏感） |
   | `203` | Account disabled/locked | AD用户属性中“帐户已禁用”或“帐户已锁定” |
   | `210` | TLS handshake failed | 服务器证书未被客户端信任，或TLS版本不兼容（建议启用TLS 1.2+） |

5. **验证证书链完整性（PEAP场景）**  
   - 使用 `openssl s_client -connect 10.10.200.10:1812 -showcerts` 检查服务端证书链  
   - 确保客户端信任根CA，并且中间证书已正确部署

## 四、安全加固建议

- ✅ 强制启用 **EAP-TLS**（证书认证）用于高敏终端（如运维工作站、IoT网关）  
- ✅ 配置交换机 `dot1x max-user 1` 防止端口复用（防MAC泛洪绕过）  
- ✅ RADIUS通信启用 **RadSec（TLS封装RADIUS）** 或至少使用强共享密钥（≥16位，含大小写字母+数字+符号）  
- ✅ 定期轮换RADIUS共享密钥与服务器证书（建议周期≤1年）  
- ❌ 禁止在生产环境使用 `EAP-MD5`（无加密、易受字典攻击）
