# 跨部门网络权限申请流程

## 概述  
本流程适用于公司内部员工因工作需要，向其他业务部门或IT基础设施团队申请访问其专属网络资源（如内网系统、测试环境、数据库集群、开发沙箱等）的权限。所有申请需遵循最小权限原则，并通过审批链完成授权。

---

## 适用范围  
- 申请人：公司正式员工（含外包人员，须由正式员工代为发起）  
- 权限类型：  
  - L2/L3 网络层访问（如特定VLAN、IP段、防火墙策略开通）  
  - 应用层访问（如Web管理后台、API网关白名单、SSH/RDP跳转权限）  
  - VPN子网路由授权（如接入 `10.200.50.0/24` 测试专网）  

> ⚠️ 注意：核心生产网段（如 `10.10.0.0/16`、`172.16.0.0/12` 中的DB/ERP子网）需额外提交《高危操作风险评估表》并经CISO办公室会签。

---

## 申请流程（共5步）

### 1. 填写《跨部门网络权限申请表》
在ITSM系统（https://itsm.company.internal） →「服务目录」→「网络与VPN」→「跨部门权限申请」中在线填写，必填字段包括：

| 字段 | 说明 | 示例 |
|------|------|------|
| 申请人姓名/工号 | 实名认证信息 | 张三 / E202100123 |
| 所属部门/岗位 | 需与HR系统一致 | 研发中心 / 后端开发工程师 |
| 目标部门/系统 | 明确被访问方 | 数据平台部 / Hive元数据服务集群 |
| 访问协议与端口 | 列出全部必要协议+端口 | `TCP/22`, `TCP/8080`, `ICMP` |
| 源IP范围 | 限定发起访问的客户端IP段（严禁填 `0.0.0.0/0`） | `10.150.10.0/24`（研发办公网） |
| 权限有效期 | 最长不超过90天，到期自动回收 | 2025-04-01 至 2025-06-30 |
| 业务依据 | 关联Jira需求号或项目立项编号 | PROJ-2025-LOGANALYSIS-007 |

### 2. 提交至直属主管审批  
- 主管需在**2个工作日内**确认：  
  ✅ 该权限与申请人当前任务强相关  
  ✅ 已完成最小权限自检（如无需root权限则不勾选sudo）  
  ❌ 若超期未审，系统自动升级提醒至部门负责人  

### 3. 目标部门技术接口人审批  
- 由目标系统所属部门指定的**网络权限接口人**（名单见[网络资源责任人矩阵表](https://wiki.company.internal/net-owner-matrix)）进行技术可行性与安全合规性审核；  
- 常见驳回原因：  
  - 未提供源IP范围或范围过大  
  - 请求端口存在已知漏洞（如 `TCP/23` Telnet）  
  - 目标服务未启用审计日志（违反《公司日志留存规范V3.2》）  

### 4. IT网络运维组执行配置  
审批通过后，网络组在**1个工作日内**完成以下操作：  
1. 在防火墙（FortiGate 6.4+）添加ACL策略，策略ID格式：`NET-APPLY-{日期}-{工号}`  
2. 更新Cisco ACI策略组（若涉及SDN环境）  
3. 同步至堡垒机（JumpServer v4.1）白名单及会话审计规则  
4. 发送配置完成通知邮件，含策略摘要与回滚命令（如 `rollback config saved NET-APPLY-20250401-E202100123`）  

### 5. 权限验证与归档  
- 申请人收到通知后 **24小时内** 完成连通性测试（建议使用 `telnet <ip> <port>` 或 `curl -v http://<host>:<port>/health`）；  
- 测试失败时，在ITSM中提交「配置异常反馈」，网络组响应SLA：**2小时定位，4小时修复**；  
- 全流程文档自动归档至知识库，保留期≥180天。

## 常见问题（FAQ）

### Q：能否临时延长权限有效期？  
A：可以。需在到期前3个工作日重新发起申请，选择「续期」类型，并注明原策略ID。**禁止手动修改防火墙策略有效期**。

### Q：申请被驳回后如何修改？  
A：在ITSM中点击「撤回并编辑」，修正后重新提交。历史驳回意见可见审批节点评论区。

### Q：遇到错误码 `ERR_NET_4031` 怎么办？  
A：该码表示“源IP未匹配防火墙入向策略”。请检查：  
1. 客户端实际出口IP是否在申请的源IP范围内（可通过 `curl ifconfig.co` 验证）；  
2. 是否启用了代理/全局VPN导致出口IP漂移；  
3. 目标系统是否部署在多AZ环境且仅开放了部分可用区路由。
