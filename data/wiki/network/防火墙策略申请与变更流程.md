# 防火墙策略申请与变更流程

> **适用范围**：公司所有需访问内部系统、云平台或跨网络区域（如办公网↔生产网、VPC↔IDC）的业务系统、开发测试环境及第三方对接场景  
> **责任主体**：申请人（业务/开发负责人）、网络运维组、安全合规组  
> **生效周期**：标准流程 3 个工作日；紧急变更（含 P1 级故障恢复）可走加急通道（≤2 小时响应，需附《紧急变更审批单》）

---

## 一、策略申请前提条件

申请前须完成以下验证：

- ✅ 目标 IP/端口已明确（禁止使用 `0.0.0.0/0` 或全端口开放）  
- ✅ 已通过《网络连通性预检表》（含源/目的地址、协议、端口、预期流量类型）  
- ✅ 涉及敏感数据（如PII、支付信息）的策略，须同步提交《数据流向安全评估报告》  
- ❌ 不接受「先开通后补单」、「测试用临时放行」等非正式申请  

---

## 二、申请流程（标准版）

### 1. 提交申请材料
通过 ITSM 系统提交【防火墙策略变更工单】，必填字段包括：

| 字段 | 要求 | 示例 |
|------|------|------|
| **策略类型** | 单选：`入向` / `出向` / `双向` | `入向` |
| **源区域** | 下拉选择：`办公网` / `DMZ` / `AWS-VPC-A` / `阿里云-VPC-B` 等 | `办公网` |
| **目的区域** | 同上，且不得与源区域相同 | `生产内网` |
| **源地址** | CIDR 格式（支持单IP、网段），禁止模糊匹配 | `10.10.50.0/24` |
| **目的地址** | 同上，须为实际业务服务器真实 IP 或负载均衡 VIP | `172.16.100.10/32` |
| **协议与端口** | TCP/UDP/ICMP + 端口范围（如 `TCP:443,8080-8090`） | `TCP:443` |
| **有效期** | 默认永久；临时策略须注明截止日期（格式：YYYY-MM-DD） | `2025-12-31` |
| **关联需求编号** | 必填（如 Jira ID、项目立项号） | `PROJ-2024-087` |

### 2. 审批环节（自动流转+人工复核）

1. **ITSM 自动校验**  
   - 检查语法合法性（如 CIDR 格式、端口范围 ≤65535）  
   - 拦截高危组合（如 `TCP:22` 从互联网入向、`UDP:161` SNMP 未加密）  
   - 若触发拦截，返回错误码：`FW-ERR-001`（非法端口）、`FW-ERR-003`（越权跨区）等  

2. **网络运维组初审（T+0.5 日）**  
   - 核验路由可达性、NAT 规则冲突、现有策略冗余度  
   - 输出《策略影响分析报告》（含潜在冲突策略ID列表）  

3. **安全合规组终审（T+1 日）**  
   - 对照《公司防火墙基线策略v3.2》审核最小权限原则符合性  
   - 敏感策略需附加渗透测试报告摘要  

4. **申请人确认**  
   - 查收邮件通知，2 小时内点击链接确认「已知悉风险并承诺按期关闭临时策略」  
   - 超时未确认，工单自动挂起  

### 3. 实施与验证

- 网络运维组在审批完成后 **2 小时内** 在指定防火墙设备（如 Palo Alto PA-5200、FortiGate 600E）执行策略部署  
- 执行后自动触发连通性探测（ICMP/TCP SYN）至目的地址端口  
- 探测失败时，立即回滚并推送告警（错误码 `FW-DEPLOY-FAIL-01`），邮件通知申请人与值班工程师  
- 成功后发送《策略开通确认函》，含：策略ID、生效时间、设备名称、日志查询路径（如 `https://panorama.company.com/logs?sid=FW-POL-2024-XXXXX`）

## 三、策略变更与下线

| 场景 | 操作方式 | 注意事项 |
|------|----------|----------|
| **策略参数修改**（如端口扩展、地址扩容） | 新建工单，选择「变更」类型，关联原策略ID | 原策略自动置为 `Deprecated`，不删除（保留审计追溯） |
| **策略临时关闭**（如系统停机维护） | 在 ITSM 中发起「策略冻结」子任务，填写冻结起止时间 | 冻结期间策略仍存在但不生效；超时自动解冻 |
| **策略永久下线** | 提交【策略清理工单】，注明下线原因及替代方案（如已迁移至零信任架构） | 安全组需在 7 日内完成策略归档与日志备份 |

## 四、常见问题（FAQ）

- **Q：能否批量申请多条策略？**  
  A：支持。在 ITSM 工单中点击「添加策略行」，最多一次性提交 20 条；每条须独立满足最小权限原则。

- **Q：策略开通后无法访问，如何排查？**  
  A：按顺序检查：  
  1. 源端 `traceroute -T -p 443 <目的IP>` 确认路径是否经过目标防火墙  
  2. 登录 Panorama/FortiManager 查看该策略命中计数（`Hit Count > 0`）  
  3. 检查目的主机防火墙（OS 层）是否拦截（如 `iptables` / `Windows Defender 防火墙`）  
  4. 抓包确认 SYN 包是否被丢弃（关键错误码：`FW-DROP-ACL-02` 表示 ACL 显式拒绝）

- **Q：紧急情况下如何 bypass 审批？**  
  A：仅限 P1 级故障（如核心交易中断），需：  
  ① 拨打 NOC 热线 + 转接网络值班经理；  
  ② 同步邮件发送《紧急变更审批单》（含故障现象、影响范围、预计恢复时间、申请人签字扫描件）；  
  ③ 变更后 24 小时内补全 ITSM 工单与事后复盘报告。
